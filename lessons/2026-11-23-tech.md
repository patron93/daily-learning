# 💻 День 40 · 2026-11-23 · architecture: API-контракты — OpenAPI, генерация клиентов и BFF

**Коротко:** если фронтенд узнаёт о смене API из Sentry, контракта у вас нет — есть договорённость в Slack. OpenAPI-спецификация, из которой генерируется Angular-клиент, а CI ловит breaking changes ещё в PR бэкенда, превращает «бэк опять поменял поле» в красную проверку до мержа. BFF при этом — место, где фронтенд-команда сама владеет формой API под свои экраны.

**Contract-first против code-first.** В code-first спецификация генерируется из кода бэкенда (декораторы NestJS `@nestjs/swagger`, Springdoc, FastAPI). Это дёшево, но контракт появляется *после* реализации, и фронт ждёт. В contract-first сначала пишут и ревьюят `openapi.yaml` (обе команды в одном PR), потом параллельно: бэкенд реализует, фронт работает на моках, сгенерированных из той же спецификации (MSW, Prism). На практике большинство команд живёт в гибриде: code-first, но спецификация — артефакт сборки, который коммитят и диффают. Главное не способ, а то, что **спецификация — единственный источник правды**, и её изменение видно в ревью.

**Генерация клиента для Angular.** Вариантов несколько: `openapi-generator` (шаблон `typescript-angular`, генерирует `@Injectable`-сервисы на `HttpClient`, тяжеловат), `ng-openapi-gen` (лёгкие функции + сервисы), Orval (умеет Angular, моки MSW и Zod-схемы) и `@hey-api/openapi-ts`, у которого есть плагин для Angular с генерацией функций под `httpResource` (на момент написания помечен как beta). Нюанс выбора: смотрите не на «красоту» кода, а на (1) tree-shaking — функции на эндпоинт лучше, чем один сервис-монолит на 200 методов, (2) как генератор обрабатывает `oneOf`/`discriminator` и `nullable` — именно здесь типы чаще всего врут, (3) можно ли получить runtime-валидацию (Zod) для критичных ответов.

![Пайплайн контракта: spec → lint и diff в CI → генерация → Angular](/img/tech/2026-11-23-api-contract.svg)

```ts
// openapi-ts.config.ts — генерация из спецификации, которую публикует бэкенд
import { defineConfig } from '@hey-api/openapi-ts';

export default defineConfig({
  input: '../api/openapi.yaml',
  output: 'src/app/api/generated',
  plugins: [{ name: '@angular/common', httpResources: true }],
});

// order-page.ts — компонент получает типизированный ресурс на сигналах
export class OrderPage {
  readonly id = input.required<string>();
  // сгенерировано: getOrderResource = (options) => httpResource(() => getOrderRequest(options()))
  readonly order = getOrderResource(() => ({ path: { orderId: this.id() } }));
}
```

**Breaking changes ловит CI, а не пользователи.** Добавьте в пайплайн бэкенда `oasdiff breaking base.yaml head.yaml --fail-on ERR`: удаление поля, смена типа, новое обязательное поле в запросе — PR краснеет. На фронте проверка «сгенерированный код не разошёлся со спекой» (`generate && git diff --exit-code`) не даёт забыть перегенерировать клиент. Сгенерированный код либо коммитят (видно в ревью, что изменилось), либо генерируют в сборке — оба варианта рабочие, плохо только смешивать.

**Где здесь BFF.** В уроке про аутентификацию (2026-11-11) BFF был нужен ради токенов. Вторая его роль — **API под экран**: агрегировать три микросервиса в один ответ `GET /bff/order-page/:id`, обрезать лишние поля, переименовать доменные термины в UI-термины. Если BFF пишет и держит фронтенд-команда (часто на NestJS), его OpenAPI-контракт тоже ваш — и тогда contract-first у вас получается почти бесплатно. Цена: ещё один сервис в проде, и соблазн утащить туда бизнес-логику. Правило: BFF собирает и адаптирует, но не принимает бизнес-решений.

Свежий контекст: OpenAPI 3.2 (сентябрь 2025) добавил иерархические теги, метод `QUERY` и описание стриминговых ответов (SSE, JSON Lines) — полезно, если вы стримите ответы LLM. Поддержка в генераторах догоняет постепенно, так что прежде чем поднимать версию, проверьте свой инструмент.

**Зачем это тимлиду:** контракт — это граница между командами в терминах Конвея. Без него каждая интеграция — переговоры и баги на стыке; с ним спор «кто сломал» решает CI, а фронт перестаёт блокироваться на бэкенде благодаря мокам из той же спецификации.

**Применить завтра:**

- Найдите в проекте рукописные интерфейсы DTO (`interface OrderDto`) и посчитайте, сколько раз за квартал они расходились с бэкендом. Это аргумент для генерации — начните с одного домена, а не со всего API.
- Договоритесь с бэкенд-лидом о шаге `oasdiff breaking` в их CI и о том, что изменения `openapi.yaml` ревьюит кто-то из фронта.
