# 💻 День 26 · 2026-11-09 · architecture: дизайн-система и библиотека компонентов — токены и версионирование

**Коротко:** дизайн-система ломается не на кнопках, а на двух вещах: где живёт «правда» о цветах и отступах (токены) и как библиотека выпускает изменения, не роняя пять команд-потребителей (версионирование). Разберём трёхуровневые токены, формат W3C DTCG, который с октября 2025 года стабилен, и правила semver для UI-библиотеки, где «breaking change» — это не только сигнатура.

**Токены: три уровня, а не палитра.** Токен — именованное дизайн-решение, отвязанное от платформы. Работает схема из трёх слоёв. **Примитивы** (*reference / primitive*): `blue-600 = #2563eb`, `space-4 = 16px` — сырой словарь, его никто не использует в компонентах напрямую. **Семантические** (*system / semantic*): `color.action.primary → blue-600`, `color.surface.danger → red-50` — это смысл, и именно тут живут темы: тёмная тема или white-label для клиента переопределяют только этот слой. **Компонентные** (*component*): `button.primary.bg → color.action.primary` — нужны точечно, когда компонент должен отличаться от общей семантики. Главное правило ревью: компонент ссылается на семантику или на свой компонентный токен, но **никогда** на примитив и тем более на hex. Тогда смена бренда — это правка одного слоя, а не grep по 400 файлам.

**Формат и пайплайн.** Design Tokens Community Group при W3C 28 октября 2025 года выпустила первую стабильную версию спецификации (2025.10). Токены описываются в JSON с полями `$value`, `$type`, `$description`, алиасы пишутся как ссылка на путь в фигурных скобках, файлы — `*.tokens.json`. Это значит, что Figma-плагины (Tokens Studio), Style Dictionary и Terrazzo читают один и тот же источник, и токены можно хранить в репозитории как код: PR, ревью, changelog. Дальше генератор собирает из JSON CSS-переменные, SCSS-карты и TS-константы. В Angular Material с M3 та же идея уже встроена: миксин `mat.theme()` выдаёт системные токены как CSS-переменные `--mat-sys-primary`, `--mat-sys-surface` и т.д., а точечные правки делаются через `mat.<компонент>-overrides()`, а не через перебивание внутренних классов. Своя библиотека должна вести себя так же: публичный API стилей — это CSS custom properties, а не селекторы.

![Токены: примитивы → семантика → компонент и пайплайн сборки](/img/tech/2026-11-09-design-tokens.svg)

```json
// tokens/semantic.tokens.json (DTCG 2025.10)
{
  "color": {
    "action": {
      "primary": { "$type": "color", "$value": "{color.blue.600}" },
      "primary-hover": { "$type": "color", "$value": "{color.blue.700}" }
    },
    "surface": {
      "danger": { "$type": "color", "$value": "{color.red.50}",
                  "$description": "Фон ошибок и деструктивных диалогов" }
    }
  }
}
```

```scss
// libs/ui/button/button.component.scss — компонент знает только семантику
:host {
  --ds-button-bg: var(--ds-color-action-primary);       // компонентный токен = точка кастомизации
  --ds-button-bg-hover: var(--ds-color-action-primary-hover);
}
button {
  background: var(--ds-button-bg);
  &:hover { background: var(--ds-button-bg-hover); }
  // ❌ background: #2563eb;  ❌ background: var(--ds-blue-600);
}
```

**Версионирование: что считать breaking.** Для UI-библиотеки semver шире, чем «изменилась сигнатура». **Major**: удалили или переименовали input/output, селектор, CSS-переменную или токен; поменяли DOM так, что ломаются тесты потребителей (harness'ы спасают, селекторы по классам — нет); подняли peer-зависимость Angular. **Minor**: новый компонент, новый input с безопасным дефолтом, новый токен. **Patch**: багфикс. Серая зона — визуальные изменения: сдвинули отступ на 4px, и у кого-то поехала вёрстка. Договоритесь заранее и запишите в CONTRIBUTING: например, «визуальные правки в рамках гайдлайна — minor с пометкой в changelog, изменение размеров компонента — major». Механика: Changesets или conventional commits генерируют версии и changelog; удаление идёт через **депрекацию на одну мажорную версию** (`@deprecated` в JSDoc, алиас старого токена на новый, warning в dev-режиме); для массовых переименований — `ng update`-схематик, который сам переписывает код потребителей. Внутри Nx-монорепо, где все приложения на одной версии, semver не нужен вовсе — там работает «сломал, сам и починил по `nx affected`», но как только у библиотеки есть внешние потребители, без версий и депрекаций начинается ад.

**Зачем это тимлиду:** дизайн-система — продукт с пользователями-разработчиками, и тимлид её команды отвечает за доверие к релизам. Если каждый minor что-то ломает, команды пиннят старую версию и форкают компоненты — через год у вас пять дизайн-систем. Токены в репозитории убирают вечный пинг-понг «а какой тут цвет?» между дизайном и фронтом: решение принимается один раз в PR, и его видно в истории.

**Применить завтра:**

- Посчитай grep'ом hex-цвета и `px`-отступы в SCSS компонентов (`rg "#[0-9a-fA-F]{3,6}" libs/`). Это метрика долга — заведи её в тикет и отслеживай, как уменьшается.
- Запиши в README библиотеки одну таблицу «что у нас major/minor/patch» с визуальными изменениями отдельной строкой и правило депрекации. Это закрывает 80% споров в ревью релизов.
