# 💻 День 41 · 2026-11-24 · ai: LLM во фронтенде — streaming-ответы и UX ожидания

**Коротко:** полный ответ модели приходит за 5–20 секунд, а первый токен — за 300–800 мс. Streaming превращает «спиннер на 15 секунд» в текст, который начинает печататься почти сразу, но тащит за собой новые проблемы: транспорт, отмену, частичные ошибки, рендер markdown на каждом токене и доступность. Разберём, как это сделать в Angular на сигналах и что из этого должно стать стандартом команды.

**Архитектура: браузер не ходит к провайдеру напрямую.** Ключ API в бандле — это публичный ключ. Фронт стучится в свой BFF (`POST /api/chat`), BFF добавляет ключ, системный промпт, лимиты и логирование и проксирует поток провайдера дальше. Транспорт почти всегда **SSE поверх `fetch`**: ответ `text/event-stream`, строки `data: …`, разделённые пустой строкой. Нюанс: нативный `EventSource` умеет только `GET` без тела и своих заголовков, поэтому для чата его не используют — читают `response.body` через `ReadableStream` и парсят события сами (или берут `@microsoft/fetch-event-source`, `eventsource-parser`). WebSocket нужен, только если поток двусторонний (голос, совместное редактирование). И проверьте прокси: nginx и некоторые CDN буферизуют ответ, и «стриминг» приходит одним куском в конце — `X-Accel-Buffering: no` на BFF.

**Angular: `resource` со `stream`.** Начиная с Angular 19.2 у `resource()` есть вариант `stream`: загрузчик возвращает не значение, а сигнал `ResourceStreamItem<T>` (`{ value }` или `{ error }`), который вы обновляете по мере прихода токенов. `abortSignal` приходит в загрузчик сам: при смене `params` или уничтожении компонента запрос отменяется — бесплатная кнопка «Стоп» и защита от гонок, когда пользователь отправил второй вопрос, не дождавшись первого.

```ts
readonly prompt = signal<string | undefined>(undefined);

readonly answer = resource({
  params: () => this.prompt(),            // undefined → ресурс простаивает
  stream: async ({ params, abortSignal }) => {
    const out = signal<ResourceStreamItem<string>>({ value: '' });
    const res = await fetch('/api/chat', {
      method: 'POST', body: JSON.stringify({ prompt: params }), signal: abortSignal,
    });
    const reader = res.body!.pipeThrough(new TextDecoderStream()).getReader();
    (async () => {
      let buf = '';
      try {
        for (;;) {
          const { done, value } = await reader.read();
          if (done) break;
          buf += value;
          const events = buf.split('\n\n');
          buf = events.pop()!;                // хвост без \n\n — ждём продолжения
          for (const e of events) {
            const delta = e.replace(/^data: /, '');
            if (delta === '[DONE]') return;
            out.update(s => ({ value: ('value' in s ? s.value : '') + JSON.parse(delta).text }));
          }
        }
      } catch (err) {
        if (!abortSignal.aborted) out.set({ error: err as Error });
      }
    })();
    return out;
  },
});
```

`answer.value()` растёт по мере прихода текста, `answer.isLoading()` и `answer.status()` дают состояния для UI, а `this.prompt.set(undefined)` или новый вопрос обрывают текущий поток. Для продакшена парсер событий лучше взять библиотечный: событие может прийти разрезанным на два чанка, бывают `event:` и `id:` строки и комментарии-пинги `:keepalive`.

**UX ожидания — это отдельный дизайн, а не спиннер.**

- **До первого токена** (TTFT) показывайте конкретный статус («Ищу в документации…»), если BFF делает RAG или вызывает инструменты: пауза в 3 секунды без объяснения выглядит как зависание.
- **Кнопка «Стоп» видна всё время генерации**, и отмена реально рвёт запрос до провайдера (BFF должен пробросить abort дальше, иначе вы платите за токены, которые никто не читает).
- **Markdown на каждом токене** — это повторный парсинг всего текста и мерцание незакрытых блоков кода. Копите дельты и рендерьте раз в кадр (`requestAnimationFrame`) или раз в 50–100 мс; HTML из модели обязательно санитизируйте — это недоверенный ввод.
- **Автоскролл только если пользователь внизу.** Прокрутил вверх читать — не дёргайте его.
- **Ошибка посреди ответа:** оставьте частичный текст, пометьте его «ответ прерван» и дайте «Повторить», а не стирайте всё в красный баннер.
- **Доступность:** `aria-live="polite"` на каждом токене превращает скринридер в пулемёт. Объявляйте статусы («Генерирую ответ», «Ответ готов»), а сам текст — по завершении или по абзацам.

**Зачем это тимлиду:** «добавим AI-чат» обычно оценивают как «форма + HTTP-запрос», а сложность сидит в стриминге, отмене, стоимости и рендере. Если не договориться о паттерне один раз, каждая фича в команде изобретёт свой парсер SSE с багом на разрезанных чанках.

**Применить завтра:**

- Вынесите стриминг в один общий сервис или фабрику `chatResource()` с тестом на «событие разрезано между чанками» и на отмену; фичи используют только её.
- Добавьте в Definition of Done для LLM-фич чек-лист: TTFT-статус, «Стоп» с отменой на бэкенде, частичная ошибка, санитизация, `aria-live` для статусов.
