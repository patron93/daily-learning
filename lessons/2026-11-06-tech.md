# 💻 День 23 · 2026-11-06 · angular: Deferrable views (@defer) — триггеры, prefetch и влияние на бандл

**Коротко:** `@defer` — это ленивая загрузка на уровне куска шаблона, а не роута: компилятор сам выносит standalone-зависимости блока в отдельный чанк и подгружает его по триггеру. Выигрыш реальный, но только если правильно выбрать **что** откладывать, **когда** загружать (prefetch) и **когда** показывать (render), и не сломать при этом CLS и SSR.

Механика: всё, что внутри `@defer`, компилятор превращает в динамический `import()`. Чтобы это сработало, зависимость должна быть **standalone** и **не упоминаться вне `@defer` в том же файле** — ни в другом месте шаблона, ни в `viewChild()`/`@ViewChild`. Иначе Angular молча загрузит её eagerly, и бандл не уменьшится. Транзитивные зависимости (то, что импортирует сам отложенный компонент) могут быть и NgModule-based — они уедут в тот же чанк.

Блок живёт в четырёх состояниях: `@placeholder` (до триггера), `@loading` (идёт загрузка), основной контент и `@error`. Триггеры (`on idle` по умолчанию, `viewport`, `interaction`, `hover`, `immediate`, `timer(…)`, `when <expr>`) комбинируются по **ИЛИ**. Ключевой приём — **разделить prefetch и render**: `@defer (on interaction; prefetch on idle)` скачает чанк, пока браузер простаивает, а отрисует по клику — пользователь не видит спиннер. `when` срабатывает один раз: если выражение потом станет `false`, контент не вернётся в placeholder.

На сервере (SSR/SSG) триггеры игнорируются и рендерится только `@placeholder`. С **incremental hydration** (включается вместе с `provideClientHydration()` в актуальных версиях) появляются `hydrate on …`-триггеры: сервер отдаёт полноценный HTML, а JS для гидрации блока приезжает по триггеру; `hydrate never` оставляет кусок статичным. Обычные `on`-триггеры тогда работают только для последующих клиентских рендеров.

![Жизненный цикл @defer: prefetch, render и состояния блока](/img/tech/2026-11-06-defer.svg)

```ts
@Component({
  selector: 'app-order-page',
  imports: [OrderSummary, OrderHistoryChart, SupportChat],
  template: `
    <app-order-summary [order]="order()" />

    <!-- тяжёлый график ниже сгиба: качаем заранее, рисуем в viewport -->
    @defer (on viewport; prefetch on idle) {
      <app-order-history-chart [orderId]="order().id" />
    } @placeholder (minimum 300ms) {
      <div class="chart-skeleton" style="height: 320px"></div>
    } @loading (after 150ms; minimum 400ms) {
      <app-spinner />
    } @error {
      <p>График не загрузился</p>
    }

    <!-- чат нужен единицам: грузим по клику, prefetch на hover -->
    @defer (on interaction(chatBtn); prefetch on hover(chatBtn)) {
      <app-support-chat />
    }
    <button #chatBtn>Помощь</button>
  `,
})
export class OrderPage {
  order = input.required<Order>();
}
```

Типичные ошибки, которые стоит ловить на ревью:

- **Отложили то, что видно сразу.** Контент above the fold под `on immediate`/`on viewport`/`on timer` даёт сдвиг макета и бьёт по CLS и LCP. Правило: откладываем то, что ниже сгиба, во вкладках, модалках, за кликом.
- **Placeholder без размеров.** Skeleton должен занимать ту же высоту, что и итоговый контент, иначе снова CLS.
- **Каскад вложенных `@defer` с одинаковыми триггерами** — пачка последовательных запросов. Внутренним блокам дают другие условия.
- **Компонент упомянут вне блока** (например, его тип в `viewChild`) — чанк не создаётся. Проверять по выводу `ng build`: в списке lazy chunks должен появиться отдельный файл.
- **Тесты.** По умолчанию TestBed проигрывает defer-блоки как в браузере; для проверки состояний — `DeferBlockBehavior.Manual` и `fixture.getDeferBlocks()` с `render(DeferBlockState.Placeholder | Loading | Complete)`.

**Зачем это тимлиду:** `@defer` — самый дешёвый рычаг для initial bundle и LCP без переделки роутинга, но он же легко превращается в «посыпали defer везде и ухудшили CLS». Нужны общие правила в команде: что откладываем, какие триггеры по умолчанию, как проверяем эффект цифрами, а не ощущениями.

**Применить завтра:**

- Открой `ng build` (или `source-map-explorer`) самой тяжёлой страницы, найди 2–3 компонента ниже сгиба или за кликом (графики, редакторы, чаты, карты) и оберни их в `@defer` с парой «render on viewport/interaction + prefetch on idle/hover». Сравни размер initial chunk до и после.
- Добавь в чек-лист ревью: «у `@defer` есть `@placeholder` с фиксированной высотой; отложенный компонент не упомянут вне блока; нет defer для контента above the fold».
