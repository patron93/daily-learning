# 💻 День 39 · 2026-11-22 · news: Chrome 158 — Web Install API и элемент install для PWA

**Коротко:** в Chrome 158 (stable по расписанию — **17 ноября 2026**) попадает **Web Install API**: метод `navigator.install()` и HTML-элемент `<install>`. Впервые сайт может сам, по клику пользователя, предложить установить PWA — и не только себя, но и **другое** веб-приложение по URL его манифеста. Для команды, у которой есть PWA или портал с несколькими внутренними приложениями, это повод пересмотреть «кнопку установки», которая сейчас держится на хрупком `beforeinstallprompt`.

**Что было до этого.** Единственный программный способ установить PWA в Chromium — событие `beforeinstallprompt`. Браузер сам решает, *когда* его выстрелить (эвристики вовлечённости), событие одноразовое, его надо поймать, сохранить, вызвать `prompt()` в нужный момент — и оно умеет ставить только **текущее** приложение. В Safari и Firefox его нет вовсе. На практике у многих команд «кнопка Установить» то появляется, то нет, и никто не может объяснить почему.

**Что даёт Web Install API.** Два входа. Первый — декларативный элемент `<install>`: браузер сам рисует доверенную кнопку со своим текстом, по клику показывает диалог установки, а результат приходит событием `installresult` (`success`, `aborted` или `invalid-data`). Второй — императивный `navigator.install()`: возвращает промис, работает только из обработчика клика (нужна *transient user activation*), умеет ставить текущее приложение или чужое — `navigator.install({ manifest, manifestId })`. Для установки **другого** приложения перед диалогом браузер спросит разрешение `web-app-installation`; это же имя у Permissions Policy, которой можно запретить установку из iframe.

Элемент сделала команда Microsoft Edge вместе с Chrome; в origin trial он был с Chrome/Edge 148 по 153. Важная оговорка: в майском посте Chrome элемент описан с атрибутом `installurl` и событиями `promptaction`/`promptdismiss`, а в актуальном (ноябрь 2026) гайде — с атрибутом `manifest` и одним событием `installresult`. API ещё «оседает», поэтому опирайтесь на текущий гайд и feature detection, а не на старые статьи.

**Требования к манифесту** — то, на чём споткнётся команда:

- для установки **текущего** приложения в манифесте обязателен явный `id`, same-origin с документом;
- чужой манифест должен отдаваться по HTTPS без редиректов и cookies, с JSON-типом (`application/manifest+json`), а его `start_url` должен быть того же origin, что и сам манифест; CORS не нужен;
- если `id` в манифесте нет, `manifestId` можно передать — но он **проверяет** вычисленный ID (от `start_url`), а не переопределяет его; несовпадение даст `DataError`.

```ts
// install-button.ts — кнопка «Установить» с прогрессивным улучшением
import { Component, signal, inject, PLATFORM_ID } from '@angular/core';
import { isPlatformBrowser } from '@angular/common';

type InstallState = 'idle' | 'installed' | 'aborted' | 'unsupported';

@Component({
  selector: 'app-install-button',
  template: `
    @if (supported) {
      <button type="button" (click)="install()">Установить приложение</button>
    } @else {
      <a href="/install-help">Как установить приложение</a>
    }
  `,
})
export class InstallButton {
  private readonly isBrowser = isPlatformBrowser(inject(PLATFORM_ID));
  // SSR: на сервере navigator нет — проверяем только в браузере
  readonly supported =
    this.isBrowser && typeof (Navigator.prototype as any).install === 'function';
  readonly state = signal<InstallState>('idle');

  async install(): Promise<void> {
    try {
      // вызываем сразу в обработчике клика: после await активация теряется
      await (navigator as any).install();
      this.state.set('installed');
    } catch (e) {
      const name = (e as DOMException).name;
      // AbortError — пользователь отказался; DataError — проблема с манифестом
      this.state.set(name === 'AbortError' ? 'aborted' : 'unsupported');
      if (name === 'DataError') console.error('Проверьте id и start_url в манифесте', e);
    }
  }
}
```

Почему кнопка, а не `<install>` прямо в шаблоне: компилятор Angular проверяет элементы по своей DOM-схеме, и новый тег без дефиса может не пройти проверку, пока схему не обновят (`CUSTOM_ELEMENTS_SCHEMA` разрешает только теги с дефисом). Проверьте на своей версии; до тех пор `navigator.install()` из обычной кнопки — самый предсказуемый путь. Плюс так вы контролируете текст и стили, а `<install>` по задумке рисует браузер, и маскировать его поверх своей кнопки запрещено.

**Попутная новость: TypeScript 7.1 RC задерживается.** По плану RC должен был выйти 10 ноября, а stable — 24 ноября, но на 18 ноября в npm всё ещё `7.0.2` как `latest` и `7.1.0-beta`; команда TS писала, что сдвигает график примерно на две недели. Если вы планировали в декабре переключать сборку на стабильный API нативного компилятора (тема урока 2026-10-25), заложите сдвиг и не привязывайте к нему релиз.

**Зачем это тимлиду:** установка PWA перестаёт быть лотереей эвристик и становится обычной фичей с предсказуемым поведением, ошибками и метриками. Для B2B-портала с несколькими внутренними приложениями (админка, отчёты, мобильный склад) появляется «каталог приложений», который ставит каждое в один клик. Но это только Chromium-браузеры (о Safari, Firefox и Android данных нет), поэтому решение — прогрессивное улучшение с фолбэком, а не замена существующего флоу.

**Применить завтра:**

- Проверьте манифесты своих PWA: есть ли явный `id`, совпадает ли origin у `start_url`, отдаётся ли манифест с JSON-типом и без редиректа. Это 15 минут в DevTools → Application → Manifest, и это нужно независимо от нового API.
- Заведите спайк на полдня: кнопка на `navigator.install()` с feature detection, `beforeinstallprompt` как фолбэк, ссылка на инструкцию для остальных браузеров. Добавьте аналитику: сколько кликов → `installed` / `AbortError` / `DataError`.
