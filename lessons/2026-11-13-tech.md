# 💻 День 30 · 2026-11-13 · angular: Control flow (@if/@for/@switch) и почему track решает производительность

**Коротко:** встроенный control flow — не просто «новый синтаксис вместо `*ngIf`». Это часть компилятора: меньше рантайма, лучшее сужение типов и новый алгоритм сверки списков в `@for`, где **`track` — это идентичность DOM-узлов**. Неправильный `track` незаметно превращает каждое обновление списка в «снести всё и нарисовать заново» или, хуже, переносит состояние одного элемента на другой.

Блоки `@if`, `@for`, `@switch` появились в v17, стали стабильными в v18, а в v20 `NgIf`, `NgFor` и `NgSwitch` объявлены deprecated (точный срок удаления смотри в release notes своей мажорной версии). Миграция автоматическая: `ng generate @angular/core:control-flow`. Плюсы против структурных директив: не нужно импортировать `NgIf`/`NgFor` (это встроено в шаблон, а не в `CommonModule`), `@if (user(); as u)` нормально сужает тип, а в `@switch` можно включить **проверку исчерпываемости**: `@default never;` заставит компилятор упасть, если в union-тип добавили новое значение без `@case`. Ограничение: сужение работает на переменных, а не на вызове сигнала, поэтому сначала `@let s = state();`, потом `@switch (s.kind)`.

Главное — `@for`. В `*ngFor` `trackBy` был опциональным, и по умолчанию Angular сравнивал элементы по ссылке. В `@for` `track` **обязателен**, и это сознательное решение: каждое выражение `track` отвечает на вопрос «какой DOM-узел (и какой экземпляр компонента) соответствует этому элементу после обновления». Отсюда три варианта и их цена:

- **`track item.id`** — правильный выбор по умолчанию. После рефетча с сервера приходят новые объекты, но с теми же `id`: Angular переиспользует существующие view и только обновляет биндинги. Если поменять порядок, DOM-узлы переезжают вместе со своим состоянием.
- **`track item`** (по ссылке) — пока данные иммутабельно приходят с сервера, каждый ответ даёт новые ссылки, и Angular **пересоздаёт все строки**: теряется фокус в инпутах, сбрасываются анимации, заново выполняются конструкторы дочерних компонентов. В dev-режиме Angular ругается предупреждением NG0956 («tracking expression caused re-creation of the entire collection»). Документация называет этот вариант крайним случаем.
- **`track $index`** — подходит только для статичных списков, которые не сортируются и не фильтруются. В динамическом списке он «приклеивает» view к позиции: удалили первую строку — и все компоненты ниже получают чужие данные через input, а их внутреннее состояние (раскрытый аккордеон, введённый текст, локальный сигнал) остаётся на месте и относится уже к другому элементу. Это не ошибка производительности, это **ошибка корректности**, и она очень плохо ловится тестами.

Ещё одна dev-подсказка — NG0955: дубликаты ключей в `track`. Обычно это `track item.name` там, где имена не уникальны, или временные элементы без id (оптимистичное добавление). Лечится стабильным ключом, например клиентским `crypto.randomUUID()` до ответа сервера.

![track в @for: id против ссылки против $index](/img/tech/2026-11-13-for-track.svg)

```ts
type OrderState =
  | { kind: 'loading' }
  | { kind: 'error'; message: string }
  | { kind: 'ready'; orders: Order[] };

@Component({
  selector: 'app-orders',
  imports: [OrderRow],
  template: `
    @let s = state();
    @switch (s.kind) {
      @case ('loading') { <app-skeleton /> }
      @case ('error') { <p class="error">{{ s.message }}</p> }
      @case ('ready') {
        @for (order of s.orders; track order.id; let i = $index, last = $last) {
          <app-order-row [order]="order" [position]="i + 1" [class.last]="last" />
        } @empty {
          <p>Заказов пока нет</p>
        }
      }
      @default never;
    }
  `,
})
export class Orders {
  state = input.required<OrderState>();
}
```

Добавят в `OrderState` вариант `{ kind: 'archived' }` — сборка упадёт на `@default never;`, а не молча покажет пустое место. Обрати внимание: в `@for` нет `break`/`continue`, фильтруй и режь данные в `computed()`, а не в шаблоне; и `$index` здесь используется только для вывода номера, а не как ключ.

Пара нюансов, на которых спотыкаются при миграции:

- **`else`-шаблоны уходят**: `*ngIf="cond; else tpl"` с отдельным `ng-template` превращается в `@if (cond) {} @else {}`, а цепочка `@else if` заменяет вложенные `ngIf`. Алиас из `@if (x; as y)` виден только внутри блока.
- **Схематик миграции копирует `trackBy`-функцию**, но если её не было, он подставит `track $index` или ссылку — это места, которые нужно перепроверить вручную в каждом динамическом списке.
- **Компоненты с внутренним состоянием внутри `@for`** (формы, редакторы, раскрывашки) — главный кандидат на баги при `track $index`.

**Зачем это тимлиду:** миграция на control flow обычно делается одной командой и одним большим PR, и именно поэтому её опасно ревьюить «по диагонали». Решения о `track` — это решения о корректности UI, а не о стиле. Хорошее командное правило превращает их из «вкусовщины» в проверяемый пункт.

**Применить завтра:**

- Найди в проекте `track $index` и `track item` (`grep -rnE 'track (\$index|\w+)\s*[;)]' src`) и пройдись по списку: всё динамическое переведи на стабильный id. Заодно открой приложение в dev-режиме и поищи в консоли NG0955/NG0956.
- Добавь в гайд команды: «в `@for` по умолчанию `track entity.id`; `$index` только для статичных списков; для дискриминированных union в `@switch` — `@default never;`».
