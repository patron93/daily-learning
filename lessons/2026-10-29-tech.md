# 💻 День 15 · 2026-10-29 · classic: Паттерны Strategy, Facade, Adapter во фронтенде

**Коротко:** три самых «рабочих» паттерна из GoF для Angular-кода. Strategy прячет *как* делать (выбор реализации), Facade прячет *сколько всего* участвует в сценарии, Adapter прячет *чужую форму* данных или API. Ценность не в названиях, а в том, что каждый отвечает на конкретную боль, и в том, чтобы не применять их там, где боли нет.

**Strategy: заменить `switch` на DI.** Признак: метод с `switch (type)` или цепочкой `if`, который растёт с каждой новой фичей (форматы экспорта, способы оплаты, правила скидок). Стратегия — это общий интерфейс плюс несколько реализаций, а выбор делается снаружи. В Angular самый естественный «реестр стратегий» — multi-провайдер `InjectionToken`: новая реализация добавляется одной строкой в `providers`, сам сервис не меняется (это и есть Open/Closed из урока про SOLID). Сам Angular построен на стратегиях: `TitleStrategy`, `RouteReuseStrategy`, `PreloadingStrategy` в роутере — вы подменяете поведение, не трогая фреймворк. Перегиб: стратегия ради двух вариантов, которые никогда не расширятся. Тогда хватит обычного `if` или функции в параметре.

**Facade: узкий API сценария.** Компонент корзины не должен знать, что под капотом store, HTTP, аналитика и тосты. Фасад — `@Injectable` с сигналами на чтение и методами-намерениями (`addItem`, `checkout`), который оркестрирует подсистемы. Плюсы для команды: компоненты становятся тонкими, тесты компонента мокают один фасад, а переход с классического NgRx на SignalStore или сервисы с сигналами меняет фасад, а не 40 компонентов. Важный нюанс: фасад — граница *сценария* (feature), а не обёртка над каждым сервисом. Фасад, который просто проксирует один сервис метод в метод, — лишний слой. Второй анти-паттерн — «God facade» на всё приложение: он быстро становится свалкой и общим местом конфликтов в PR.

**Adapter: чужая форма — на границе.** DTO бэкенда со `snake_case`, датами-строками и `null` вместо пустых массивов не должен протекать в шаблоны. Адаптер (чаще всего чистая функция `mapOrder(dto)`) переводит внешнюю форму в доменную модель один раз, на входе. Тот же приём для SDK вендоров: аналитика, карты, платежи прячутся за вашим интерфейсом, и смена вендора — это новый адаптер, а не поиск по всему коду. В Angular адаптеров полно: `ControlValueAccessor` адаптирует любой компонент к формам, а `DateAdapter` в Angular Material позволяет datepicker работать с `Date`, date-fns или Luxon (`provideDateFnsAdapter()` и т.п.). Отличие от фасада: адаптер не добавляет поведения и не оркестрирует, он только переводит интерфейс.

```ts
// Strategy: реестр через multi-провайдер
export interface Exporter { format: 'csv' | 'xlsx' | 'pdf'; export(rows: Row[]): Blob; }
export const EXPORTERS = new InjectionToken<Exporter[]>('EXPORTERS');

@Injectable({ providedIn: 'root' })
export class ExportService {
  private readonly exporters = inject(EXPORTERS);
  export(format: Exporter['format'], rows: Row[]): Blob {
    const exporter = this.exporters.find(e => e.format === format);
    if (!exporter) throw new Error(`No exporter for ${format}`);
    return exporter.export(rows);
  }
}
// app.config.ts: новая стратегия = одна строка
// { provide: EXPORTERS, useClass: CsvExporter, multi: true },

// Adapter: внешняя форма → домен, один раз на границе
export const mapOrder = (dto: OrderDto): Order => ({
  id: dto.order_id,
  createdAt: new Date(dto.created_at),
  items: dto.items ?? [],
});

// Facade: сценарий корзины для компонентов
@Injectable({ providedIn: 'root' })
export class CartFacade {
  private readonly store = inject(CartStore);
  private readonly api = inject(CartApi);
  private readonly analytics = inject(Analytics);

  readonly items = this.store.items;        // Signal, только чтение
  readonly total = this.store.total;

  async checkout(): Promise<void> {
    const order = mapOrder(await this.api.checkout(this.store.items()));
    this.store.clear();
    this.analytics.track('checkout', { id: order.id });
  }
}
```

**Зачем это тимлиду:** общий словарь ускоряет ревью: «вынеси это в стратегию» или «DTO протекает мимо адаптера» короче и точнее, чем абзац объяснений. Ещё важнее — договориться, *где* паттерны обязательны (адаптер на каждой границе с API и вендорами, фасад на уровне feature), а где запрещены как оверинжиниринг. Без такой договорённости одни делают фасад на каждый сервис, другие кладут DTO прямо в шаблоны, и кодовая база расползается. AI-агенты, кстати, охотно генерируют лишние слои «по учебнику», так что правило стоит записать и в `AGENTS.md`.

**Применить завтра:**

- Поищите в кодовой базе `switch` по типу или статусу в сервисах, которые менялись в последних 5+ PR. Это кандидаты на Strategy; обсудите один на ближайшем техсинке.
- Проверьте, где типы из сгенерированного API-клиента (`*Dto`) используются в компонентах и шаблонах. Если таких мест много, заведите правило: DTO живут только в data-access слое, наружу выходят доменные модели через адаптеры (в Nx это можно закрепить тегами и `enforce-module-boundaries`).
