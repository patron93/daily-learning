# 💻 День 16 · 2026-10-30 · Angular: Zoneless — change detection без zone.js и как мигрировать

**Коротко:** zone.js запускал change detection «на всякий случай» после любого `setTimeout`, промиса или события. Zoneless-режим работает наоборот: Angular перерисовывает только когда его явно уведомили (сигнал, событие в шаблоне, `async`-пайп, `markForCheck()`). `provideZonelessChangeDetection()` стабилен с Angular 20.2, а с v21 новые проекты создаются вообще без zone.js. Для команды главный вопрос не «включать ли», а «какой код у нас молча перестанет обновлять экран».

### Как было и как стало

zone.js монкипатчит все асинхронные API браузера: `setTimeout`, `Promise.then`, `addEventListener`, `XMLHttpRequest`. Когда очередь микрозадач пустеет, `NgZone` эмитит `onMicrotaskEmpty`, и `ApplicationRef.tick()` проверяет всё дерево (или OnPush-ветки, помеченные dirty). Отсюда и магия «просто присвоил `this.items = data` в `subscribe`, и всё обновилось», и цена: лишние проверки на каждый `mousemove` или таймер сторонней библиотеки, около 30 КБ полифила, нечитаемые стектрейсы и `runOutsideAngular` как ручная оптимизация.

В zoneless-режиме планировщик (`ChangeDetectionScheduler`) запускает tick только по уведомлению. Уведомляют: запись в сигнал, который читает шаблон; обработчики событий в шаблоне и `host`; `AsyncPipe`; `ComponentRef.setInput()`; `ChangeDetectorRef.markForCheck()`; присоединение/отсоединение view. **Не уведомляет:** обычное присваивание поля в `setTimeout`, `.then()`, колбэке сторонней библиотеки или в `subscribe()` без `async`-пайпа. Это и есть главная категория багов при миграции: экран «застывает» без ошибок в консоли.

Нюанс, который часто упускают: компонент с `ChangeDetectionStrategy.OnPush` и сигналами — уже почти zoneless-совместимый. OnPush-компонент и так требует явных уведомлений, поэтому если команда последние пару лет писала на OnPush + сигналах, миграция будет скучной. Если в коде много Default-стратегии и мутаций полей в подписках — это и есть объём работы.

![zone.js против zoneless](/img/tech/2026-10-30-zoneless.svg)

```ts
// app.config.ts — Angular 20.2+: явно; в новых проектах v21+ это уже поведение по умолчанию
export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRouter(routes),
    provideHttpClient(),
  ],
};
// и убрать "zone.js" из polyfills в angular.json (и из test-таргета)

// ❌ В zoneless экран не обновится: поле меняется вне уведомлений
export class ReportComponent {
  status = 'idle';
  start() {
    this.api.generate().then(() => (this.status = 'done')); // тишина
  }
}

// ✅ Сигнал сам уведомит планировщик
export class ReportComponent {
  readonly status = signal<'idle' | 'running' | 'done'>('idle');
  start() {
    this.status.set('running');
    this.api.generate().then(() => this.status.set('done'));
  }
}

// 🩹 Временный мост для легаси-кода, который пока нельзя переписать
private readonly cdr = inject(ChangeDetectorRef);
onLegacyWidgetChange(v: string) {
  this.value = v;
  this.cdr.markForCheck();
}
```

### План миграции, который реально работает

1. **Сначала OnPush везде**, без снятия zone.js. Включи схематик/линт-правило на `OnPush` для новых компонентов и переводи старые. Всё, что ломается на OnPush, сломается и в zoneless, но OnPush ломается заметнее и по одному компоненту.
2. **Найди «тихие» присваивания:** `subscribe(x => this.field = x)`, `setTimeout`, `.then`, колбэки сторонних виджетов (карты, графики, редакторы). Переводи на `signal`, `toSignal()` или `async`-пайп.
3. **Тесты:** `fakeAsync`/`tick`/`flush` завязаны на zone.js. В zoneless используй `await fixture.whenStable()`, а для таймеров фейковые таймеры Vitest/Jest. Тест, который проходит только с `fixture.detectChanges()` после ручного присваивания, часто прячет тот самый баг из пункта 2.
4. **Переключение:** `provideZonelessChangeDetection()`, убрать zone.js из polyfills. Проверь, не используют ли библиотеки `NgZone.onStable`/`onMicrotaskEmpty` — в zoneless они не эмитят. Если приложение обновлено до v21+, но к zoneless ещё не готово, держи явный `provideZoneChangeDetection()` в конфиге, чтобы поведение не зависело от умолчаний версии.
5. **Ошибки:** без зоны необработанные ошибки из `setTimeout` и промисов могут не дойти до `ErrorHandler`. Проверь, что Sentry/логгер ловит `window.onerror` и `unhandledrejection`.

**Зачем это тимлиду:** zoneless — это не флаг производительности, а смена контракта «кто отвечает за перерисовку». Раньше фреймворк страховал небрежный код, теперь ответственность на авторе компонента. Это решение уровня команды: нужны правила ревью («никаких мутаций полей в подписках»), линт и порядок миграции, иначе получите баги «иногда не обновляется», которые не ловит ни один тест.

**Применить завтра:**

- Посчитай масштаб: `grep` по `ChangeDetectionStrategy.Default` (и компонентам без явной стратегии), `fakeAsync` и `.subscribe(` с присваиванием `this.`. Три числа дадут честную оценку миграции для бэклога.
- Добавь в чеклист ревью пункт «состояние, видимое в шаблоне, — только сигнал, `async`-пайп или input» и включи OnPush по умолчанию в `angular.json` (`schematics` → `changeDetection: "OnPush"`).
