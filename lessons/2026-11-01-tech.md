# 💻 День 18 · 2026-11-01 · news: Node.js 26 стал LTS — план обновления для Angular-команды

**Коротко:** 28 октября 2026 Node.js 26 перешёл в статус LTS под кодовым именем **Lithium** и будет получать обновления до конца апреля 2029. Сам релиз 26.13.0 — только смена метки, но для команды это сигнал: теперь Node 26 можно ставить в CI и Docker как основную версию. Есть нюанс: Angular 21 Node 26 официально не поддерживает, а Angular 22 — да.

**Что случилось.** У Node.js чётные мажоры полгода живут как «Current», а потом становятся LTS: в эту фазу прод-командам и рекомендуется переходить. Релиз [26.13.0 'Lithium'](https://nodejs.org/en/blog/release/v26.13.0) по коду совпадает с 26.12.1 (security-релиз от 21 октября), изменились только метаданные вроде `process.release.lts`. Сейчас на поддержке три линии: **26** (Active LTS до апреля 2029), **24** (LTS, до апреля 2028) и **22** (maintenance, до апреля 2027). Node 20 закончил жизнь ещё в апреле 2026 — если он у вас где-то остался в CI или в базовом Docker-образе, это уже не «пора бы», а дыра без патчей. Днём позже, 29 октября, вышла первая альфа Node 27 — её пока не трогаем.

**Что приносит линия 26** (из [релиза 26.0.0](https://nodejs.org/blog/release/v26.0.0), май 2026):

- **Temporal включён по умолчанию** — новый API дат и времени вместо `Date`: неизменяемые объекты, явные часовые пояса, нормальная арифметика дат. Для бэкенда, SSR и скриптов больше не нужен полифил.
- **V8 14.6** (Chromium 146): `Map.prototype.getOrInsert()` / `getOrInsertComputed()` и `Iterator.concat()`.
- **Undici 8** под капотом встроенного `fetch`.
- Удалены: флаг `--experimental-transform-types`, старые внутренние модули `_stream_readable` и компания, `http.Server.prototype.writeHeader()`. `module.register()` теперь выдаёт runtime-предупреждение — это касается кастомных loader'ов (часто в тестовых и build-скриптах).
- Подвох при переходе с 22/24: начиная с Node 25 официальные Linux-бинарники линкуются с **libatomic**, которой может не быть в slim-образах — `node` просто не стартует.

![Node.js LTS и поддержка в Angular](/img/tech/2026-11-01-node-lts.svg)

**Нюанс для Angular.** По [таблице совместимости](https://angular.dev/reference/versions) Angular 22 требует `^22.22.3 || ^24.15.0 || ^26.0.0`, а Angular 21 — `^20.19.0 || ^22.12.0 || ^24.0.0`. То есть Node 26 — это повод сначала обновить Angular до 22, а не наоборот. И ещё одна ловушка: Temporal в Node не значит Temporal в браузере. Код Angular-приложения выполняется у пользователя, поэтому если вы начнёте писать `Temporal.Now` в общих утилитах, при SSR всё будет работать, а в браузерах без поддержки — упадёт. Для фронтенда сначала проверка поддержки в целевых браузерах (или полифил), для SSR-only и Node-скриптов — можно уже сейчас.

Минимальный набор, чтобы версия Node в команде была одной и той же везде:

```json
// package.json
{
  "engines": { "node": "^24.15.0 || ^26.0.0" }
}
```

```yaml
# .github/workflows/ci.yml — матрица на время перехода
strategy:
  matrix:
    node: [24, 26]
steps:
  - uses: actions/setup-node@v4
    with:
      node-version: ${{ matrix.node }}
```

```ts
// Node 26: без полифила, только в серверном коде (SSR, скрипты)
const deadline = Temporal.Now.plainDateISO('Europe/Warsaw').add({ days: 14 });

// V8 14.6: группировка без проверки has/get/set
const byTeam = new Map<string, string[]>();
for (const pr of prs) byTeam.getOrInsertComputed(pr.team, () => []).push(pr.id);
```

Плюс файл `.nvmrc` (или `.node-version`) с `26` в корне: его читают nvm, fnm, Volta, большинство CI и `actions/setup-node` через `node-version-file`.

**Зачем это тимлиду:** версия рантайма — классическая «ничья» зона ответственности. У одного разработчика Node 22, в CI 24, в Docker-образе для SSR вообще 20, и баги «у меня работает» появляются именно здесь. LTS-переход — естественный момент один раз навести порядок и закрепить правило: «мы на Active LTS, обновляемся в течение квартала после перехода новой линии в LTS». Это предсказуемо для команды и понятно для бизнеса, а связку с Angular (сначала Angular 22, потом Node 26) стоит явно положить в роадмап, чтобы никто не начал обновление не с того конца.

**Применить завтра:**

- Сделайте инвентаризацию: `node -v` во всех местах — CI-раннеры, Dockerfile для SSR, локальные машины, serverless-функции. Если где-то Node 20 — это задача с приоритетом безопасности, а не техдолг.
- Заведите ветку с матрицей `[24, 26]` в CI: она сразу покажет, ломаются ли ваши кастомные loader'ы (`module.register()`), build-скрипты и Docker-образ (libatomic). Если проект ещё на Angular 21 — запланируйте сначала `ng update` до 22.
