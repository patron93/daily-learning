# 💻 День 5 · 2026-10-19 · ai: как работают LLM — токены, контекстное окно, temperature

**Коротко:** LLM не «читает текст» и не «думает словами»: она по одному предсказывает следующий токен по всему, что лежит в контекстном окне, и выбирает его из распределения вероятностей. Из этой простой механики вытекает почти всё, что важно на практике: цена, лимиты, «забывчивость» в длинных диалогах и недетерминированность ответов.

**Токены — валюта всего.** Перед моделью текст режется токенизатором (обычно вариант BPE) на куски из словаря: частые английские слова — один токен, редкие слова, идентификаторы и код — несколько. Русский и польский текст обычно дороже английского: на ту же мысль уходит заметно больше токенов, а значит, больше денег, задержки и места в контексте. Отсюда же классические слабости: модель плохо считает буквы в слове и иногда спотыкается на арифметике с длинными числами — она видит не символы, а куски. Лимиты, тарифы и `max_tokens` считаются именно в токенах, и у разных моделей токенизаторы разные: число токенов для одного и того же промпта не переносится между провайдерами. Точно считать лучше через API провайдера (у Anthropic есть отдельный endpoint подсчёта токенов), а не через `text.length / 4`.

**Контекстное окно — это вся «память».** У модели нет состояния между запросами: каждый вызов получает заново system prompt, историю диалога, вложенные документы, описания инструментов и их результаты — и всё это вместе с будущим ответом должно поместиться в окно. Чат «помнит» прошлое только потому, что клиент каждый раз отправляет историю целиком; когда она не влезает, её обрезают или сжимают. Большое окно не значит «всё одинаково хорошо видно»: исследование «Lost in the Middle» (Liu et al., 2023) показало, что качество заметно падает, когда нужный факт лежит в середине длинного контекста, а не в начале или в конце. Практический вывод: важные инструкции и вопрос — в начало или в конец, мусор — вон, а длинный контекст ещё и медленнее и дороже. Порядок важен и для денег: prompt caching срабатывает только на совпадающем префиксе, поэтому статичное (инструкции, схемы, документация) кладут первым, а изменчивое — последним.

**Temperature — ручка случайности, а не «креативности».** На каждом шаге модель выдаёт оценки (logits) для всех токенов словаря; они делятся на temperature и превращаются softmax в вероятности. Низкая температура заостряет распределение (почти всегда берётся самый вероятный токен), высокая — сглаживает его. `top_p` (nucleus sampling) обрезает хвост маловероятных токенов. Два нюанса для senior: даже `temperature: 0` не гарантирует побайтово одинаковых ответов (вычисления на GPU и батчинг дают недетерминированность), а у части свежих моделей ручка вообще отобрана — reasoning-модели OpenAI не принимают нестандартную `temperature`, а Claude Opus 4.7 отвечает ошибкой 400 на нестандартные `temperature`/`top_p`/`top_k`. Детерминизм теперь добывают не температурой, а structured output, JSON-схемами, валидацией и evals.

```ts
// Бюджет контекста: решаем, что отрезать, ДО запроса, а не ловим ошибку от API
interface ContextBudget {
  window: number;      // размер окна модели в токенах
  maxOutput: number;   // резерв под ответ (max_tokens)
}

function fitHistory(
  system: number,                       // токены system prompt + описаний инструментов
  history: { tokens: number }[],        // сообщения, старые → новые
  { window, maxOutput }: ContextBudget,
): number {
  let budget = window - maxOutput - system;
  let keepFrom = history.length;
  // идём с конца: свежие сообщения важнее старых
  for (let i = history.length - 1; i >= 0 && budget - history[i].tokens >= 0; i--) {
    budget -= history[i].tokens;
    keepFrom = i;
  }
  return keepFrom; // всё, что раньше, — в summary или под нож
}
```

**Зачем это тимлиду:** почти каждый вопрос про AI-фичу или AI-инструмент в команде упирается в эти три понятия. «Почему агент забыл договорённость из начала сессии?» — контекст переполнился или факт утонул в середине. «Почему счёт вырос вдвое?» — в каждый запрос улетает вся история плюс огромные результаты инструментов, а префикс не кешируется. «Почему тест на LLM-фичу флакает?» — потому что вы проверяете точный текст недетерминированной системы. Понимая механику, вы задаёте правильные вопросы на дизайн-ревью и не покупаете «модель побольше» там, где нужно урезать контекст.

**Применить завтра:**

- Если в продукте или во внутренних инструментах есть вызовы LLM, добавьте в логи `input_tokens`, `output_tokens` и cache hit из ответа API — через неделю будет видно, куда уходят токены и деньги.
- Договоритесь в команде: тесты LLM-фич проверяют структуру и свойства ответа (схема, наличие ключевых полей, ограничения), а не совпадение строки; `temperature` из конфигов новых моделей — убираем, а не подбираем.
