# 💻 День 37 · 2026-11-20 · angular: Signal Forms — формы на сигналах (стабильны с v22)

**Коротко:** Signal Forms (`@angular/forms/signals`) появились экспериментально в v21 и стали стабильными в Angular 22. Главная идея: форма не хранит копию данных, как `FormGroup`, а строится поверх твоего `signal()` с моделью. Валидация описывается схемой, состояние полей (`valid`, `errors`, `touched`) — это сигналы, а значит, никаких `valueChanges`, подписок и `updateValueAndValidity()`.

В Reactive Forms у тебя две правды: доменная модель и дерево `FormControl` со своим значением. Между ними постоянно ходят `patchValue()` и `getRawValue()`, а производное состояние («кнопка активна, если…») собирается через RxJS. Signal Forms убирают вторую правду. Ты пишешь `model = signal<Profile>(...)`, затем `f = form(this.model, schema)` и получаешь `FieldTree`: к полям обращаешься как к свойствам (`f.email`, `f.address.city`, `f.items[0].name`), а вызов поля `f.email()` возвращает `FieldState` с сигналами `value`, `errors()`, `valid()`, `touched()`, `dirty()`, `pending()`, `disabled()`, `hidden()`, `readonly()`. Ввод в `<input [formField]="f.email">` пишет **прямо в модель**: `model()` всегда актуален.

Схема — это функция, которая один раз выполняется при создании формы и регистрирует правила на путях: `required(path.email)`, `min(path.age, 18)`, `pattern(...)`, свой `validate(path, ({ value }) => ...)`, асинхронный `validateHttp(...)`, а для массивов `applyEach(path.items, ItemSchema)`. Правила реактивны: условие `when` или логика `disabled(path.x, ...)` зависят от других полей через сигналы, и Angular сам пересчитывает только то, что изменилось. Асинхронные правила запускаются только после того, как прошли синхронные; пока они идут, `pending()` равен `true`, а `valid()` равен `false`. Отправка — через `submit()`: он помечает поля как touched, не даёт отправить невалидную форму и выставляет `submitting()`.

Что поменялось при переходе в stable (важно, если кто-то в команде пробовал v21): директива `Field` с селектором `[field]` стала **`FormField` / `[formField]`**, а для тега `<form>` появилась директива **`FormRoot`** (`[formRoot]`): она отменяет нативный submit, ставит `novalidate` и передаёт отправку в Signal Forms. Это значит, что валидация **не** использует нативный Constraint Validation API: селектор `:invalid` и `validity` ничего не знают о твоих правилах, стили ошибок строй на `field().invalid()`.

```ts
import { Component, inject, signal } from '@angular/core';
import { OrderApi } from './order-api';
import {
  form, FormField, FormRoot, submit,
  required, email, min, minLength, applyEach, validate,
  type SchemaPathTree,
} from '@angular/forms/signals';

interface OrderLine { sku: string; qty: number }
interface Order { email: string; company: string; isCompany: boolean; lines: OrderLine[] }

function LineSchema(line: SchemaPathTree<OrderLine>) {
  required(line.sku, { message: 'Укажи товар' });
  min(line.qty, 1, { message: 'Минимум 1 шт.' });
}

@Component({
  selector: 'app-order-form',
  imports: [FormField, FormRoot],
  template: `
    <form [formRoot]="f" (submit)="send($event)">
      <input type="email" [formField]="f.email" />
      @if (f.email().touched() && f.email().invalid()) {
        @for (e of f.email().errors(); track e.kind) {
          <small class="error">{{ e.message }}</small>
        }
      }

      <label><input type="checkbox" [formField]="f.isCompany" /> Фирма</label>
      <input [formField]="f.company" />

      @for (line of f.lines; track $index) {
        <input [formField]="line.sku" />
        <input type="number" [formField]="line.qty" />
      }

      <button [disabled]="f().submitting()">Отправить</button>
    </form>
  `,
})
export class OrderForm {
  private readonly api = inject(OrderApi);
  readonly model = signal<Order>({ email: '', company: '', isCompany: false, lines: [] });

  readonly f = form(this.model, (path) => {
    required(path.email, { message: 'Email обязателен' });
    email(path.email, { message: 'Неверный email' });
    // правило зависит от другого поля — это просто чтение сигнала
    required(path.company, {
      message: 'Для фирмы нужно название',
      when: ({ valueOf }) => valueOf(path.isCompany),
    });
    minLength(path.lines, 1, { message: 'Добавь хотя бы одну позицию' });
    applyEach(path.lines, LineSchema);
    validate(path.lines, ({ value }) =>
      value().length > 50 ? { kind: 'tooMany', message: 'Не больше 50 позиций' } : null,
    );
  });

  send(event: Event) {
    event.preventDefault();
    submit(this.f, {
      action: async () => {
        await this.api.createOrder(this.model()); // модель уже актуальна, getRawValue() не нужен
      },
    });
  }
}
```

**Нюансы, о которые спотыкаются:**

- **`required` на массиве** считает `[]` валидным. Для «хотя бы одна строка» нужен `minLength`.
- **Скрытые, disabled и readonly поля не валидируются** и не участвуют в `valid()`/`dirty()`. Но DOM за тебя никто не скрывает: `@if (!f.company().hidden())` пишешь сам.
- **`input type="date"`** отдаёт полночь по UTC: границы `minDate`/`maxDate` задавай через `new Date('2026-06-01')`, а не через локальный конструктор, иначе в Польше (UTC+1/+2) получишь сдвиг на день.
- **Свои контролы** реализуют `FormValueControl` (минимум — `value = model<T>()`) вместо `ControlValueAccessor`. CVA продолжает работать через совместимость, так что дизайн-систему не нужно переписывать в один день.
- **Миграция не обязана быть «большим взрывом»**: есть `SignalFormControl` для вставки сигнального поля в существующий `FormGroup` и пакет `@angular/forms/signals/compat`. Reactive Forms не deprecated.

**Зачем это тимлиду:** формы — самая «толстая» часть типичного enterprise-Angular: подписки на `valueChanges`, ручная синхронизация с моделью, `distinctUntilChanged` и утечки. Signal Forms убирают целый класс багов и делают формы тестируемыми как обычные функции от сигнала. Но это новый ментальный режим, и без договорённостей команда получит смесь трёх подходов (template-driven, reactive, signal) в одном репозитории. Решение «где и когда переходим» — твоё.

**Применить завтра:**

- Зафиксируй в ADR правило: **новые** формы пишем на Signal Forms, старые Reactive Forms не трогаем, пока в них не нужна крупная доработка. Кастомные контролы дизайн-системы постепенно переводим на `FormValueControl`.
- Возьми одну небольшую, но «живую» форму (фильтр списка или настройки профиля) и перепиши её в паре с разработчиком: сравните количество кода, тестов и подписок. Это лучше любой презентации.
