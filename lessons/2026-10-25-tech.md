# 💻 День 11 · 2026-10-25 · news: TypeScript 7.1 Beta и путь Angular на нативный компилятор

**Коротко:** 20 октября Microsoft выпустила TypeScript 7.1 Beta. Главное в ней не новые фичи языка, а публичный программный API для Go-компилятора: именно его отсутствие держало Angular, Vue, Svelte и typescript-eslint на TypeScript 6. RC запланирован на 10 ноября, стабильный релиз на 24 ноября 2026.

**Что случилось.** TypeScript 7.0 (летом 2026) переписал компилятор на Go и ускорил сборки в разы, но вышел без JS-API: им можно пользоваться как CLI (`tsc`), а вот инструменты, которые подключаются к компилятору как к библиотеке, остались за бортом. `@angular/compiler-cli` как раз такой: он сам парсит код, трансформирует декораторы и проверяет типы в шаблонах через API TypeScript. Поэтому Angular 22 официально живёт на TS 6.0, а TS 7 в Angular-проекте пока годится только для отдельной быстрой проверки типов.

**Что в 7.1.** Новый API разбит на точки входа: `typescript/sync`, `typescript/async` (на промисах), `typescript/fs` (виртуальные файловые системы на запрос) и `typescript/ast` с подмодулями `is` и `factory`. Состояние хранится в иммутабельных snapshots: `snapshot.update(...)` порождает новый снимок, а старый остаётся доступным для запросов. Экземпляры API и Program нужно явно освобождать (`api.close()`, `program.dispose()` или ключевое слово `using`): за JS-объектами стоит Go-процесс, и сборщик мусора его не закроет. Ещё две заметные вещи: **content mappers** (ключ `contentMappers` в tsconfig подключает пакет, который учит `tsc` проверять `.vue`, `.svelte`, `.astro`, `.mdx`; из CLI они запускаются только с флагом `--runExternalCode`, потому что это исполняемый чужой код) и стабильный `--target es2026` / `--lib es2026` (`Array.fromAsync`, `Iterator.concat`, `Math.sumPrecise`, base64/hex у `Uint8Array`). По бенчмаркам Microsoft проверка типов быстрее 7.0 в 1,2–1,9 раза при памяти на 15–50% меньше.

![Angular и TypeScript 7: что меняет 7.1](/img/tech/2026-10-25-ts7-angular.svg)

**Нюанс для Angular.** Даже 7.1 не даёт transformer API, на котором построен эмит Angular. По данным Ng-News, команда Angular разделяет компилятор на два конвейера: парсинг и трансформацию кода берёт Oxc (Rust-тулчейн, на котором уже работают Vite и другие инструменты), а TypeScript 7.1 отвечает только за проверку типов, включая шаблоны. Соответствующий PR уже в `main`, и поддержка может появиться в одном из минорных релизов 22.x, но точной версии команда не обещает. До этого peer dependency Angular останется на TS 6.0, а `--legacy-peer-deps` ради TS 7 — плохая идея.

Ломающие изменения в 7.1 тоже есть: обновлённые DOM-типы в `lib.d.ts` и более строгое поведение distributive conditional types, где параметр после распределения больше не считается связанным с другими параметрами, ограниченными исходным типом. Если у вас в shared-библиотеке хитрые утилитарные типы, проверьте их на бете заранее.

Пока ждём Angular, TS 7 можно поставить рядом с TS 6 и гонять быструю проверку типов в CI (схема из обзора OpenReplay; под pnpm/Yarn проверьте, на какую версию указывает `tsc`):

```json
{
  "devDependencies": {
    "typescript": "npm:@typescript/typescript6@^6.0.2",
    "@typescript/native": "npm:typescript@^7.0.2"
  },
  "scripts": {
    "typecheck:fast": "node node_modules/@typescript/native/bin/tsc --noEmit -p tsconfig.app.json"
  }
}
```

Всё, что импортирует `typescript` (Angular CLI, typescript-eslint), получает 6.0, а быстрый `tsc` 7 проверяет `.ts`-код. Шаблоны он не видит: их по-прежнему проверяет `ng build`.

**Зачем это тимлиду:** переход на TS 7 — самое большое ускорение фронтенд-тулинга за годы, но для Angular-команды это не «обновить пакет», а зависимость от двух чужих роадмапов. Тимлиду важно не обещать бизнесу ускорение CI раньше, чем Angular его поддержит, и заранее снять риски: утилитарные типы, кастомные ESLint-правила на type-aware API, собственные скрипты поверх `typescript` как библиотеки. Это всё сломается или потребует переписывания на новый API со snapshots и `dispose`.

**Применить завтра:**

- Заведите задачу «готовность к TS 7»: в отдельной ветке поставьте `typescript@beta` рядом с 6.0 через alias и прогоните `tsc --noEmit` по самому большому проекту. Запишите время против текущего и список новых ошибок: это аргумент и план миграции одновременно.
- Проведите инвентаризацию: какие внутренние скрипты, генераторы и ESLint-правила импортируют `typescript` как библиотеку. Это код, который придётся адаптировать под новый API, когда TS 6 перестанет быть основным.
