# 💻 День 4 · 2026-10-18 · architecture: монорепо на Nx и границы модулей

**Коротко:** монорепо без правил за полгода превращается в «большой ком грязи»: любой файл может импортировать любой другой. Nx решает это тегами проектов и линт-правилом `@nx/enforce-module-boundaries`, которое превращает архитектурную схему в проверку, падающую в CI.

**Граница — это проект, а не папка.** В Nx единица архитектуры — проект (app или lib) со своим `project.json` или полем `nx` в `package.json`. Правило `@nx/enforce-module-boundaries` по умолчанию, ещё до всяких тегов, ловит три вещи: импорт другого проекта по относительному пути вместо алиаса (`@org/feature-cart`), циклические зависимости между проектами и статический импорт библиотеки, которая где-то грузится лениво (`loadChildren`) — такой импорт тихо затягивает её в основной бандл. Уже это стоит включить в первый же день.

**Теги дают архитектуру.** Каждому проекту вешаются теги в нескольких измерениях. Классика: `scope:*` (домен — `scope:checkout`, `scope:admin`, `scope:shared`) и `type:*` (слой — `type:app`, `type:feature`, `type:ui`, `type:data-access`, `type:util`). Затем в `depConstraints` описывается, кто от кого может зависеть. Несколько подходящих правил складываются по AND, так что «домен» и «слой» проверяются независимо. В значениях тегов работают `*` (любые), glob вида `scope:*` и регулярки в форме `"/^scope.*/"`. Важный нюанс: проект **без тегов** без явного правила с `*` не может зависеть ни от чего — удобная ловушка для забытых новых библиотек.

**Больше, чем слои.** У правила есть `notDependOnLibsWithTags` (запреты вместо белого списка), `bannedExternalImports` / `allowedExternalImports` (например, запретить `@angular/material` во всём, кроме `type:ui`, или `rxjs` в `type:util`), `allSourceTags` (правило для проектов, у которых есть *все* перечисленные теги), `enforceBuildableLibDependency` (buildable-библиотека не может тянуть небилдуемую) и `banTransitiveDependencies` (нельзя импортировать пакет, которого нет в `package.json`). `allow` — это аварийный люк: каждое исключение там — техдолг, который стоит видеть в ревью.

```js
// eslint.config.mjs (flat config)
'@nx/enforce-module-boundaries': ['error', {
  enforceBuildableLibDependency: true,
  depConstraints: [
    // слои
    { sourceTag: 'type:app',         onlyDependOnLibsWithTags: ['type:feature', 'type:ui', 'type:data-access', 'type:util'] },
    { sourceTag: 'type:feature',     onlyDependOnLibsWithTags: ['type:ui', 'type:data-access', 'type:util'] },
    { sourceTag: 'type:ui',          onlyDependOnLibsWithTags: ['type:ui', 'type:util'],
      bannedExternalImports: ['@angular/common/http', '@ngrx/store'] },   // UI не ходит в сеть и в стор
    { sourceTag: 'type:data-access', onlyDependOnLibsWithTags: ['type:data-access', 'type:util'] },
    { sourceTag: 'type:util',        onlyDependOnLibsWithTags: ['type:util'] },
    // домены
    { sourceTag: 'scope:checkout',   onlyDependOnLibsWithTags: ['scope:checkout', 'scope:shared'] },
    { sourceTag: 'scope:shared',     onlyDependOnLibsWithTags: ['scope:shared'] },
  ],
}],
```

```json
// libs/checkout/feature-cart/project.json
{ "name": "checkout-feature-cart", "tags": ["scope:checkout", "type:feature"] }
```

**Зачем это тимлиду:** архитектурные договорённости на конфлюенсе живут до первого дедлайна, а правило в CI — пока вы его не выключите. Теги делают границы явными и ревьюемыми: изменение `depConstraints` — это архитектурное решение, видно в диффе, у него есть автор и обсуждение. Плюс прямой выигрыш в скорости: чем чище граф, тем точнее `nx affected` и кеш, и тем меньше пересобирается на каждый PR. Границы `scope:*` к тому же часто совпадают с зонами ответственности команд — тот же закон Конвея, только записанный в конфиг.

**Применить завтра:**

- Откройте `nx graph` и посмотрите на свой реальный граф. Повесьте теги `type:*` хотя бы на 5–10 самых используемых библиотек и включите правило с уровнем `warn`, чтобы оценить масштаб нарушений до того, как оно начнёт ломать CI.
- Договоритесь: новая библиотека без тегов не проходит ревью, а каждая запись в `allow` сопровождается тикетом на её удаление.
