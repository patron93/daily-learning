# 💻 День 34 · 2026-11-17 · ai: MCP — как дать AI-агенту знания вашего проекта

**Коротко:** Model Context Protocol (MCP) — открытый протокол, через который AI-агент (Claude Code, Copilot, Cursor, Gemini CLI) вызывает внешние инструменты и читает данные: «USB-C для LLM». Для фронтенд-команды это способ перестать надеяться, что модель «знает Angular 22», и дать ей актуальную документацию, ваш design system и CLI проекта. Свежая ревизия спецификации 2026-07-28 сделала протокол stateless, и это меняет то, как пишут серверы.

### Как устроено

Три роли. **Host** — приложение с моделью (IDE, агент в терминале). Внутри него на каждый подключённый сервер создаётся **client**. **Server** — отдельный процесс или HTTP-сервис, который отдаёт возможности. Общаются они JSON-RPC сообщениями через один из двух транспортов: **stdio** (host запускает сервер как дочерний процесс, типично для локальных инструментов) или **Streamable HTTP** (удалённый сервер, обычно с OAuth).

Сервер отдаёт три вида примитивов, и разница между ними важнее, чем кажется:

- **Tools** — действия, которые **модель решает вызвать сама**: «найди пример», «запусти тесты». У каждого — имя, описание и JSON Schema аргументов. Описание — это фактически промпт: по нему модель решает, когда звать инструмент.
- **Resources** — данные, которые **выбирает приложение или пользователь** (файл, страница документации, запись по URI). Они подмешиваются в контекст, а не «вызываются».
- **Prompts** — готовые шаблоны, которые **запускает пользователь** (в IDE они видны как slash-команды).

### Что поменялось в 2026-07-28

Предыдущая версия (2025-11-25) была stateful: соединение начиналось с рукопожатия `initialize`, а HTTP-сессия держалась заголовком `Mcp-Session-Id`. Это плохо жило за балансировщиком и в serverless. В новой ревизии:

- **Нет рукопожатия и сессий.** Каждый запрос сам несёт версию протокола и возможности клиента в `_meta`; вместо `initialize` есть необязательный `server/discover`. Если серверу нужно состояние между вызовами, он возвращает явный handle и получает его обратно обычным аргументом.
- **Multi Round-Trip Requests.** Если серверу посреди вызова нужно что-то от пользователя или клиента, он не шлёт встречный запрос, а возвращает `resultType: "input_required"`, и клиент повторяет исходный запрос с ответами.
- **Roots, Sampling и Logging объявлены устаревшими** (минимум 12 месяцев до удаления): пути передавайте аргументами инструментов, логируйте в stderr или OpenTelemetry. Долгие задачи (tasks) ушли в официальное расширение.
- Списки инструментов кешируются (`ttlMs`) и должны отдаваться в стабильном порядке — ради prompt caching на стороне модели.

Практический вывод: если вы пишете свой сервер сейчас, делайте инструменты **без скрытого состояния** — всё нужное приходит в аргументах. Такой сервер одинаково хорошо работает и по stdio, и за любым балансировщиком.

### MCP для Angular уже есть: `ng mcp`

Angular CLI сам является MCP-сервером. Положите в репозиторий `.vscode/mcp.json` (у Cursor — `.cursor/mcp.json` с ключом `mcpServers`):

```json
{
  "servers": {
    "angular-cli": {
      "command": "npx",
      "args": ["-y", "@angular/cli", "mcp", "--read-only"]
    }
  }
}
```

По умолчанию сервер даёт `search_documentation` (поиск по официальной документации нужной версии), `find_examples`, `get_best_practices`, `list_projects` (проекты в воркспейсе) и `onpush_zoneless_migration` (план перехода на OnPush). Экспериментальные инструменты (`build`, `test`, `e2e`, `modernize`, `devserver.*`) включаются флагом `-E`. Флаг `--read-only` оставляет только инструменты, которые не меняют проект, `--local-only` — те, что не ходят в интернет. Главная польза — агент перестаёт генерировать `*ngIf` и NgModule там, где команда давно на control flow и standalone: он сверяется с документацией вашей версии, а не с памятью модели.

### Свой сервер: каталог design system за 30 строк

Самое ценное, чего модель не знает, — ваши внутренние вещи: компоненты библиотеки, токены, контракты API. Минимальный stdio-сервер на официальном TypeScript SDK (API ветки 1.x):

```ts
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { z } from 'zod';
import catalog from './dist/components.json'; // генерируется из Storybook в CI

const server = new McpServer({ name: 'acme-ui', version: '1.4.0' });

server.registerTool(
  'find_component',
  {
    title: 'Найти компонент Acme UI',
    description:
      'Ищет компонент дизайн-системы Acme UI по назначению. ' +
      'Вызывай ПЕРЕД тем, как писать новый компонент кнопки, модалки, таблицы и т.п.',
    inputSchema: { query: z.string().describe('что нужно, например "диалог подтверждения"') },
  },
  async ({ query }) => {
    const hits = catalog
      .filter((c) => (c.name + ' ' + c.purpose).toLowerCase().includes(query.toLowerCase()))
      .slice(0, 5);
    const text = hits.length
      ? hits.map((c) => `${c.selector} — ${c.purpose}\nimport: ${c.import}\n${c.example}`).join('\n\n')
      : 'Ничего не найдено: подходящего компонента нет, можно писать свой.';
    return { content: [{ type: 'text', text }] };
  },
);

await server.connect(new StdioServerTransport());
```

Нюансы, на которых спотыкаются:

- **Описание инструмента решает всё.** «Ищет компоненты» модель проигнорирует; «вызывай ПЕРЕД тем, как писать новую кнопку» — нет. Пишите, *когда* звать, а не только *что* он делает.
- **Мало крупных инструментов лучше, чем много мелких.** Каждое описание съедает контекст на каждом запросе. 5–10 инструментов на сервер — разумный потолок.
- **Отвечайте коротко и структурно.** Ответ инструмента тоже идёт в контекст: топ-5 с примером импорта лучше, чем весь каталог.
- **stdout — только для протокола.** Любой `console.log` в stdio-сервере ломает JSON-RPC: логируйте в stderr.

### Безопасность: сервер — это код с вашими правами

Локальный MCP-сервер запускается от имени разработчика: у него есть доступ к файлам, токенам в `.env`, сети. Плюс у MCP своя атака — **prompt injection через ответы инструментов**: текст из тикета, веб-страницы или README может содержать «инструкции» для модели. Командные правила: только серверы из проверенного списка, версии закреплены (не `@latest` для чужих пакетов), по умолчанию `--read-only` и минимум прав у токенов, действия, которые что-то меняют (merge, deploy, запись в БД), — только с подтверждением человека.

**Зачем это тимлиду:** AI-инструменты в команде уже используются, вопрос только в том, на каком контексте. MCP — способ сделать этот контекст **общим и управляемым**: один `mcp.json` в репозитории, и у всех агентов одна документация, один design system и одни правила безопасности. Это тот же «golden path», что и общий ESLint-конфиг, только для агентов.

**Применить завтра:**

- Добавьте в репозиторий `.vscode/mcp.json` с `angular-cli` в режиме `--read-only` и попросите двух человек неделю сравнивать ответы агента с ним и без него.
- Составьте список из 3–5 «вещей, которые агент постоянно делает не так» (наши компоненты, наши API, наши соглашения). Каждая — кандидат на инструмент в командном MCP-сервере или хотя бы на строку в `AGENTS.md`.
