# Инструкция для ежедневного запуска

Этот файл Claude читает при каждом запуске запланированной задачи.
Всё поведение настраивается здесь: чтобы что-то поменять, достаточно отредактировать этот файл.

Уроки приходят одним запуском в 19:53 по Варшаве: задача **Daily learning: все треки** делает три урока подряд (`polish` → `tech` → `electric`), публикует их одним push и присылает **одно** письмо со ссылками на все три.

Режим запуска задаёт промпт задачи:

- **`ТРЕК: all`** (основной режим). Выполни общие шаги один раз, затем шаги 1–7 трека `polish`, шаги 1–5 трека `tech` и шаги 1–5 трека `electric` по порядку, каждый трек отдельным коммитом (`lesson: YYYY-MM-DD <трек>`, урок и файл квиза в одном коммите). Шаги «Проверка» (npm test) и «Commit и push» не повторяй для каждого трека: после всех трёх уроков один раз запусти проверку, сделай `git pull --rebase` и один `git push`. Дальше раздел «Публикация и доставка» в режиме `all`: один деплой, одно письмо, одно сообщение в чат.
- **`ТРЕК: polish` / `tech` / `electric`** (старый режим, по задаче на трек). Выполняй **только** шаги своего трека и общие шаги.

Если один трек в режиме `all` не получился (ошибка, которую не удалось исправить), не бросай остальные: откати незакоммиченные изменения этого трека, сделай остальные и в письме честно скажи, какой урок не вышел и почему.

Уроки публикуются на сайте **https://patron93.github.io/daily-learning/** (VitePress, деплой через GitHub Actions при каждом push в `main`, workflow `Deploy site`). В письмо и в чат идёт ссылка на урок, а не весь текст.

## Общие шаги (все треки)

1. `git pull` в `main`. Прочитай `profile.md`, `feedback.md`, `state.json` и шаблон своего трека: `templates/polish.md`, `templates/tech.md` или `templates/electric.md` (в режиме `all` все три). Посмотри последние 3 урока своего трека (в режиме `all` каждого трека) в `lessons/`, чтобы не повторяться по стилю и темам.
2. **Номер дня N.** Если `state.last_run` равен сегодняшней дате, то N = `state.day` (другой трек уже начал день). Иначе N = `state.day + 1`; запиши `day = N` и `last_run = сегодня`.
3. **Защита от дубля.** Если `state.<трек>_last_run` уже равен сегодняшней дате и файл урока трека за сегодня существует, ничего не создавай и не перезаписывай. Файл квиза (`lessons/YYYY-MM-DD-<трек>.quiz.json`) входит в урок: его тоже не создавай и не перезаписывай. В режиме одного трека просто пришли в чат короткое сообщение, что урок уже был, и закончи. В режиме `all` пропусти только этот трек (в письме дай ссылку на готовый урок с пометкой «уже был»); если все три уже были, письмо не отправляй, а напиши об этом в чат.

## Трек `polish`

1. Открой `polish/vocabulary.json`. Повторение: выбери до 5 слов, у которых `next_review <= сегодня` (сначала самые просроченные). Они нужны только для обновления SRS в шаге 6: в урок их не выписывай, квиз сам подбирает прошлые слова для повторения.
2. Новые слова: добавь 5 новых слов уровня A1–A2. Их не должно быть в `vocabulary.json` (проверь поле `pl`, учитывая разные формы). Слова желательно связать одной темой дня: еда, транспорт, работа, urząd, врач, магазин, IT-офис и т.д.
3. Главный блок дня берётся по ротации из `state.json → polish_rotation`: `grammar` → `words_deep` → `grammar` → `fact`.
   - `grammar`: возьми следующий непройденный пункт из `polish/grammar.md` (первый с `[ ]`), объясни его просто, на русском, с 3–4 примерами и сравнением с русским или белорусским, если это помогает. Отметь пункт `[x] (YYYY-MM-DD)`.
   - `words_deep`: разбор группы слов: ложные друзья переводчика (например, «uroda», «zapomnieć», «dywan»), устойчивые выражения или разговорные фразы.
   - `fact`: интересный факт о языке или культуре Польши, связанный с языком.
4. Файл квиза `lessons/YYYY-MM-DD-polish.quiz.json`: 8–10 вопросов по теме дня (главный блок: `grammar`, `words_deep` или `fact`), типы `choice` и `gap`. `explain` пиши на русском, примеры на польском. Переводы слов в обе стороны сайт генерирует сам из `vocabulary.json`, в файл их не клади. Пример (полная схема в `docs/features/001-lesson-quiz.md`):

   ```json
   {"date":"2026-10-17","track":"polish","topic":"Винительный падеж","questions":[{"id":"acc-1","type":"choice","prompt":"Mam ___ (siostra).","options":["siostrę","siostra","siostry","siostrą"],"answer":"siostrę","explain":"Mieć + biernik: -a → -ę."},{"id":"acc-2","type":"gap","prompt":"Piję ___ (kawa) codziennie.","answers":["kawę"],"explain":"Pić + biernik."}]}
   ```

   Правила: `choice` — от 2 до 5 уникальных `options`, `answer` входит в них; `gap` — непустой список `answers`; `id` уникален в файле; `prompt` и `explain` непустые; `date` и `track` совпадают с именем файла.

5. Собери урок по `templates/polish.md` и сохрани в `lessons/YYYY-MM-DD-polish.md`. Последняя секция урока — `## 🧩 Квиз` с тегом `<LessonQuiz date="YYYY-MM-DD" track="polish" />`: подставь сегодняшнюю дату.
6. Обнови `polish/vocabulary.json`:
   - новые слова: `box: 1`, `added: сегодня`, `next_review: сегодня + 1 день`;
   - повторённые слова: `box += 1` (максимум 5), `next_review = сегодня + интервал[box]`, где интервалы такие: 1→1, 2→3, 3→7, 4→14, 5→30 дней. `reviews += 1`.
7. В `state.json`: `polish_last_run = сегодня`, сдвинь `polish_rotation.next_index` на следующий элемент (по кругу).
8. Проверка: `npm install --no-audit --no-fund --no-package-lock && npm test` в корне репозитория. Если тесты упали, поправь файл квиза и запусти снова. Если `npm` недоступен в песочнице, пропусти проверку и положись на CI: невалидный квиз-файл сломает деплой, и сработает запасной вариант из раздела «Публикация и доставка».
9. Commit и push в `main` с сообщением `lesson: YYYY-MM-DD polish` (урок и файл квиза в одном коммите; перед push сделай `git pull --rebase`).
10. Проверь деплой и доставь урок по разделу «Публикация и доставка». Ссылка: `https://patron93.github.io/daily-learning/lessons/YYYY-MM-DD-polish`. В письме и в чате: номер дня, тема польского, 5 новых слов с переводом, фраза «В конце урока есть квиз» и ссылка. Тема письма: `📚 День N · 🇵🇱 <тема польского>`.

## Трек `tech`

1. Профразвитие (тимлид, Angular-фронтенд, плюс бэкенд и AI). Ротация по `state.json → tech_rotation`: `angular` → `leadership` → `news` → `architecture` → `ai` → `backend` → `classic`.
   - `news`: сделай веб-поиск свежих новостей за последнюю неделю (Angular, TypeScript, web platform, AI-инструменты для разработчиков). Выбери одну самую полезную новость и дай ссылку на источник.
   - Если в `feedback.md` есть запрос на конкретную тему урока `tech` на сегодняшнюю дату, он важнее ротации: сделай урок по нему (объём и формат тоже по запросу) и `tech_rotation.next_index` в шаге 5 не сдвигай.
   - Для остальных категорий возьми первую подходящую неотмеченную тему из `tech/topics.md`. Можно и свою, если она лучше, но её не должно быть в разделе «Пройдено».
   - Формат: что это (2–3 абзаца), зачем это тимлиду, пример кода, если уместен, «как применить завтра в команде» (1–2 пункта), ссылка для углубления. Проверяй факты веб-поиском, если тема касается версий или API.
2. Отметь тему `[x]` и добавь её в раздел «Пройдено» в `tech/topics.md` с датой.
3. Собери урок по `templates/tech.md` и сохрани в `lessons/YYYY-MM-DD-tech.md`. Последняя секция урока — `## 🧩 Квиз` с тегом `<LessonQuiz date="YYYY-MM-DD" track="tech" />`: подставь сегодняшнюю дату.
4. Файл квиза `lessons/YYYY-MM-DD-tech.quiz.json`: 8–10 вопросов типа `choice` по теме дня (без `gap`). Вопросы проверяют понимание нюансов, а не факты-пустышки. У каждого вопроса `explain` на русском: почему правильный ответ верен. Формат как в примере трека `polish` (шаг 4), но `track: "tech"` и только `choice`; правила там же.
5. В `state.json`: `tech_last_run = сегодня`, сдвинь `tech_rotation.next_index` на следующий элемент (по кругу).
6. Проверка: `npm install --no-audit --no-fund --no-package-lock && npm test` в корне репозитория. Если тесты упали, поправь файл квиза и запусти снова. Если `npm` недоступен в песочнице, пропусти проверку и положись на CI (см. шаг 8 трека `polish`).
7. Commit и push в `main` с сообщением `lesson: YYYY-MM-DD tech` (урок и файл квиза в одном коммите; перед push сделай `git pull --rebase`).
8. Проверь деплой и доставь урок по разделу «Публикация и доставка». Ссылка: `https://patron93.github.io/daily-learning/lessons/YYYY-MM-DD-tech`. В письме и в чате: номер дня, категория и тема, 1–2 фразы о сути и ссылка. Тема письма: `📚 День N · 💻 <тема tech>`.

## Трек `electric`

Цель ученика: самому поменять проводку в доме, собрать щит для квартиры с умным домом и спроектировать дом с солнечными панелями и обычной сетью. Уровень и пожелания смотри в `profile.md` (раздел «Электрика»).

1. Тип урока по `state.json → electric_rotation`: `theory` → `theory` → `theory` → `practice`.
   - `theory`: первый пункт с `[ ]` в модулях 0–8 файла `electric/curriculum.md`, по порядку. Модули идут от базовой физики, безопасности и основ к щиту, умному дому, дому и PV: не перескакивай вперёд.
   - Пока не пройден модуль 0, ротацию не применяй: каждый урок — `theory` по модулю 0, а `electric_rotation.next_index` не сдвигай. Объясняй с нуля, без опоры на школьную физику: каждый новый термин определяй простыми словами, начинай с бытовой аналогии, формулы давай только с расшифровкой каждой буквы и одним посчитанным примером.
   - `practice`: первый пункт с `[ ]` в разделе «Практикум». Это разбор задачи с решением по шагам: расчёт, схема, подбор оборудования. Опирайся только на то, что уже пройдено; если практикум требует непройденной темы, возьми следующий подходящий пункт практикума.
   - Формат: как устроено и почему (2–3 абзаца), схема или расчёт в блоке ```` ```text ````, 3–5 польских терминов с переводом, блок `::: warning Безопасность`, «На практике» (как это выглядит в реальной квартире или доме, частые ошибки) и ссылка для углубления.
   - Иллюстрации и видео: по разделу «Иллюстрации и видео».
   - Нормы, цифры и законы Польши (PN-HD 60364, Warunki techniczne, требования OSD, SEP, net-billing, программы дотаций) проверяй веб-поиском: они меняются. Ссылайся на первоисточник или известный ресурс (sep.com.pl, сайт OSD, gov.pl, документация производителя), а не на форумы.
2. Отметь пункт `[x] (YYYY-MM-DD)` и добавь его в раздел «Пройдено» в `electric/curriculum.md`: `- YYYY-MM-DD · модуль · тема` (для практикума модуль — `практикум`).
3. Собери урок по `templates/electric.md` и сохрани в `lessons/YYYY-MM-DD-electric.md`. Последняя секция урока — `## 🧩 Квиз` с тегом `<LessonQuiz date="YYYY-MM-DD" track="electric" />`: подставь сегодняшнюю дату.
4. Файл квиза `lessons/YYYY-MM-DD-electric.quiz.json`: 8–10 вопросов типа `choice` по теме дня (без `gap`). Хорошие вопросы — на понимание и на решения: «какой автомат и сечение», «что сработает при…», «что не так в этой схеме», небольшие расчёты с готовыми вариантами ответа, плюс 1 вопрос на польский термин. `explain` на русском. Формат как в примере трека `polish` (шаг 4), но `track: "electric"` и только `choice`; правила там же.
5. В `state.json`: `electric_last_run = сегодня`; если модуль 0 уже пройден, сдвинь `electric_rotation.next_index` на следующий элемент (по кругу).
6. Проверка: `npm install --no-audit --no-fund --no-package-lock && npm test` в корне репозитория. Если тесты упали, поправь файл квиза и запусти снова. Если `npm` недоступен в песочнице, пропусти проверку и положись на CI (см. шаг 8 трека `polish`).
7. Commit и push в `main` с сообщением `lesson: YYYY-MM-DD electric` (урок и файл квиза в одном коммите; перед push сделай `git pull --rebase`).
8. Проверь деплой и доставь урок по разделу «Публикация и доставка». Ссылка: `https://patron93.github.io/daily-learning/lessons/YYYY-MM-DD-electric`. В письме и в чате: номер дня, модуль и тема, 1–2 фразы о сути и ссылка. Тема письма: `📚 День N · ⚡ <тема электрики>`.

**Безопасность в уроках электрики (обязательно):**

- Любая работа описывается только на обесточенной цепи, с проверкой отсутствия напряжения индикатором. Никаких советов «как сделать под напряжением».
- Чётко разделяй, что можно сделать самому, а что по закону делает электрик с uprawnienia SEP: подключение к сети, pomiary odbiorcze и протокол, работа в złącze и до счётчика, zgłoszenie PV do OSD. Ученик может проектировать, собирать и готовить, а проверку и подключение доверяет специалисту.
- Не упрощай до опасного: если правильный ответ «зависит от условий», так и скажи и объясни, от чего.

## Публикация и доставка (все треки)

1. После push найди через GitHub MCP (`actions_list`, список запусков workflow `deploy.yml`) запуск для своего коммита (`head_sha`). Жди его завершения, проверяя примерно раз в 30 секунд, но не дольше 8 минут.
2. Если запуск завершился с `conclusion: success`, открой страницу урока через WebFetch (curl из песочницы до github.io закрыт) и убедись, что на ней есть заголовок урока. GitHub Pages иногда обновляется с задержкой до минуты: если страницы ещё нет, подожди и попробуй ещё раз 2–3 раза. Если WebFetch недоступен, успешного деплоя достаточно.
3. Письмо через Gmail на адрес из `profile.md`: короткое HTML-письмо с содержанием, указанным в шаге трека, и заметной ссылкой «Открыть урок».
4. Короткое сообщение в чат (SendUserMessage) с тем же содержанием и ссылкой.
5. Если деплой упал или не закончился за 8 минут: в письмо положи урок целиком (HTML), как запасной вариант, и добавь ссылку на файл в репозитории `https://github.com/patron93/daily-learning/blob/main/lessons/<файл>`. В чате и в письме скажи, что сайт не обновился, и коротко назови причину из логов (`get_job_logs`).

**Режим `all`.** Деплой один, на коммит после единственного push (`head_sha`); через WebFetch проверь все три страницы. Вместо трёх писем отправь одно:

- тема: `📚 День N · 🇵🇱 <тема польского> · 💻 <тема tech> · ⚡ <тема электрики>`;
- три блока подряд, у каждого своя заметная ссылка «Открыть урок» и содержание из шага «Проверь деплой и доставь урок» своего трека (польский: тема и 5 новых слов с переводом; tech: категория, тема и суть; электрика: модуль, тема и суть);
- в конце фраза «В конце каждого урока есть квиз».

Сообщение в чат тоже одно, с тремя ссылками. Если деплой упал, запасной вариант из пункта 5 действует для всех трёх уроков в том же одном письме.

## Иллюстрации и видео (все треки)

Визуальные материалы делай сам, без картинок из интернета (лицензии и недоступность хостов).

- **Схемы:** SVG-файл в `public/img/<трек>/YYYY-MM-DD-<имя>.svg`, в уроке `![описание](/img/<трек>/...svg)` (VitePress сам добавит base). У SVG свой светлый фон `rect`, чтобы он читался и в тёмной теме. Анимация внутри SVG (`animate`, `animateMotion`), если она объясняет процесс.
- **Интерактив:** Vue-компонент в `.vitepress/theme/components/`, регистрация в `.vitepress/theme/index.ts`, в уроке тег `<ИмяКомпонента />` (пример: `CircuitDemo` в уроке 2026-10-23 electric). Если подходящий компонент уже есть, используй его. Всегда проверяй `npm run build`.
- **Видео:** в конце урока, перед квизом, строка `**Видео:** [название](ссылка)` по теме дня. Ссылку на конкретный ролик давай только если нашёл её веб-поиском и она точно по теме; иначе ссылка на поиск YouTube по теме дня.
- Сколько и что рисовать:
  - `electric`: 1–3 схемы на урок обязательно (цепи, щит, расчёты), интерактив где уместно.
  - `tech`: 1–2 диаграммы там, где объясняется архитектура, поток данных, жизненный цикл, сравнение подходов (`ng`-компоненты, DI, RxJS-потоки, слои). Для `news` диаграмма нужна, только если она помогает.
  - `polish`: 1 наглядный элемент на урок, если он помогает: таблица падежных окончаний цветом, схема «вопрос → падеж → окончание», карточка ложных друзей, картинка ситуации (магазин, urząd) в виде простой SVG-иллюстрации. Для произношения и слов ссылка на видео с носителем языка.
  - Если в теме дня наглядность ничего не добавляет, пропусти схему, но строку `**Видео:**` оставь.

## Формат markdown для сайта

- Спойлеры (если нужны): `::: details Показать ответы` … `:::`. Отдельных ответов к упражнениям больше нет: их заменяет квиз.
- Блок `::: warning Безопасность` … `:::` в уроках электрики обязателен.
- Не используй `{{` и сырые угловые скобки вне блоков кода: VitePress прогоняет markdown через Vue, и сборка упадёт. Дженерики вроде `Signal<T>` пиши в обратных кавычках или в блоке кода. Единственный сырой тег, который разрешён в уроке, — `<LessonQuiz date="YYYY-MM-DD" track="polish|tech|electric" />` (кроме `<sub>` в подвале, как в шаблонах). Строки в `*.quiz.json` тоже не содержат `{{`.
- Первая строка `# …` — заголовок урока, из него строится меню сайта: `# 🇵🇱 День N · YYYY-MM-DD · <тема>` и `# 💻 День N · YYYY-MM-DD · <категория>: <тема>` и `# ⚡ День N · YYYY-MM-DD · <модуль>: <тема>` (модуль коротко: «Щит», «Умный дом», «PV», «Практикум» и т.п.).

## Правила

- Язык объяснений русский. Польские примеры и термины всегда с переводом. Для новых слов указывай род (m/ż/n) и, если слово неочевидное, ударение или подсказку по произношению.
- Объём: каждый трек читается за 4–6 минут.
- Если пользователь оставил отзыв в `feedback.md`, учти его и не удаляй.
- Если Gmail недоступен, всё равно сохрани урок и сделай push; в сообщении в чат укажи, что письмо не ушло, и дай ссылку.
- Никогда не удаляй историю; только дописывай. Старые уроки (`lessons/YYYY-MM-DD.md`, до разделения) не трогай.
