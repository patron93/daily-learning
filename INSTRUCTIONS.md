# Инструкция для ежедневного запуска

Этот файл Claude читает при каждом запуске запланированной задачи.
Всё поведение настраивается здесь: чтобы что-то поменять, достаточно отредактировать этот файл.

Урок приходит в два захода, с разницей примерно 8 минут:

| Трек | Задача | Время (Варшава) |
|---|---|---|
| `polish` | Daily learning: польский | 19:53 |
| `tech` | Daily learning: профразвитие | 20:01 |

В промпте каждой задачи указан её трек. Выполняй **только** шаги своего трека и общие шаги.

Уроки публикуются на сайте **https://patron93.github.io/daily-learning/** (VitePress, деплой через GitHub Actions при каждом push в `main`, workflow `Deploy site`). В письмо и в чат идёт ссылка на урок, а не весь текст.

## Общие шаги (оба трека)

1. `git pull` в `main`. Прочитай `profile.md`, `feedback.md`, `state.json` и шаблон своего трека: `templates/polish.md` или `templates/tech.md`. Посмотри последние 3 урока своего трека в `lessons/`, чтобы не повторяться по стилю и темам.
2. **Номер дня N.** Если `state.last_run` равен сегодняшней дате, то N = `state.day` (другой трек уже начал день). Иначе N = `state.day + 1`; запиши `day = N` и `last_run = сегодня`.
3. **Защита от дубля.** Если `state.<трек>_last_run` уже равен сегодняшней дате и файл урока трека за сегодня существует, ничего не создавай и не перезаписывай. Файл квиза (`lessons/YYYY-MM-DD-<трек>.quiz.json`) входит в урок: его тоже не создавай и не перезаписывай. Просто пришли в чат короткое сообщение, что урок уже был, и закончи.

## Трек `polish`

1. Открой `polish/vocabulary.json`. Повторение: выбери до 5 слов, у которых `next_review <= сегодня` (сначала самые просроченные). Они нужны только для обновления SRS в шаге 6: в урок их не выписывай, квиз сам подбирает прошлые слова для повторения.
2. Новые слова: добавь 5 новых слов уровня A1–A2. Их не должно быть в `vocabulary.json` (проверь поле `pl`, учитывая разные формы). Слова желательно связать одной темой дня: еда, транспорт, работа, urząd, врач, магазин, IT-офис и т.д.
3. Главный блок дня берётся по ротации из `state.json → polish_rotation`: `grammar` → `words_deep` → `grammar` → `fact`.
   - `grammar`: возьми следующий непройденный пункт из `polish/grammar.md` (первый с `[ ]`), объясни его просто, на русском, с 3–4 примерами и сравнением с русским или белорусским, если это помогает. Отметь пункт `[x] (YYYY-MM-DD)`.
   - `words_deep`: разбор группы слов: ложные друзья переводчика (например, «uroda», «zapomnieć», «dywan»), устойчивые выражения или разговорные фразы.
   - `fact`: интересный факт о языке или культуре Польши, связанный с языком.
4. Файл квиза `lessons/YYYY-MM-DD-polish.quiz.json`: 8–10 вопросов по теме дня (главный блок: `grammar`, `words_deep` или `fact`), типы `choice` и `gap`. `explain` пиши на русском, примеры на польском. Переводы слов в обе стороны сайт генерирует сам из `vocabulary.json`, в файл их не клади. Пример (полная схема в `docs/features/001-lesson-quiz.md`):

   ```json
   {"date":"2026-10-17","track":"polish","topic":"Винительный падеж","questions":[{"id":"acc-1","type":"choice","prompt":"Mam ___ (siostra).","options":["siostrę","siostra","siostry","siostrą"],"answer":"siostrę","explain":"Mieć + biernik: -a → -ę."},{"id":"acc-2","type":"gap","prompt":"Piję ___ (kawa) codziennie.","answers":["kawę"],"explain":"Pić + biernik."}]}
   ```

   Правила: `choice` — от 2 до 5 уникальных `options`, `answer` входит в них; `gap` — непустой список `answers`; `id` уникален в файле; `prompt` и `explain` непустые; `date` и `track` совпадают с именем файла.

5. Собери урок по `templates/polish.md` и сохрани в `lessons/YYYY-MM-DD-polish.md`. Последняя секция урока — `## 🧩 Квиз` с тегом `<LessonQuiz date="YYYY-MM-DD" track="polish" />`: подставь сегодняшнюю дату.
6. Обнови `polish/vocabulary.json`:
   - новые слова: `box: 1`, `added: сегодня`, `next_review: сегодня + 1 день`;
   - повторённые слова: `box += 1` (максимум 5), `next_review = сегодня + интервал[box]`, где интервалы такие: 1→1, 2→3, 3→7, 4→14, 5→30 дней. `reviews += 1`.
7. В `state.json`: `polish_last_run = сегодня`, сдвинь `polish_rotation.next_index` на следующий элемент (по кругу).
8. Проверка: `npm install --no-audit --no-fund --no-package-lock && npm test` в корне репозитория. Если тесты упали, поправь файл квиза и запусти снова. Если `npm` недоступен в песочнице, пропусти проверку и положись на CI: невалидный квиз-файл сломает деплой, и сработает запасной вариант из раздела «Публикация и доставка».
9. Commit и push в `main` с сообщением `lesson: YYYY-MM-DD polish` (урок и файл квиза в одном коммите; перед push сделай `git pull --rebase`).
10. Проверь деплой и доставь урок по разделу «Публикация и доставка». Ссылка: `https://patron93.github.io/daily-learning/lessons/YYYY-MM-DD-polish`. В письме и в чате: номер дня, тема польского, 5 новых слов с переводом, фраза «В конце урока есть квиз» и ссылка. Тема письма: `📚 День N · 🇵🇱 <тема польского>`.

## Трек `tech`

1. Профразвитие (тимлид, Angular-фронтенд, плюс бэкенд и AI). Ротация по `state.json → tech_rotation`: `angular` → `leadership` → `news` → `architecture` → `ai` → `backend` → `classic`.
   - `news`: сделай веб-поиск свежих новостей за последнюю неделю (Angular, TypeScript, web platform, AI-инструменты для разработчиков). Выбери одну самую полезную новость и дай ссылку на источник.
   - Для остальных категорий возьми первую подходящую неотмеченную тему из `tech/topics.md`. Можно и свою, если она лучше, но её не должно быть в разделе «Пройдено».
   - Формат: что это (2–3 абзаца), зачем это тимлиду, пример кода, если уместен, «как применить завтра в команде» (1–2 пункта), ссылка для углубления. Проверяй факты веб-поиском, если тема касается версий или API.
2. Отметь тему `[x]` и добавь её в раздел «Пройдено» в `tech/topics.md` с датой.
3. Собери урок по `templates/tech.md` и сохрани в `lessons/YYYY-MM-DD-tech.md`. Последняя секция урока — `## 🧩 Квиз` с тегом `<LessonQuiz date="YYYY-MM-DD" track="tech" />`: подставь сегодняшнюю дату.
4. Файл квиза `lessons/YYYY-MM-DD-tech.quiz.json`: 8–10 вопросов типа `choice` по теме дня (без `gap`). Вопросы проверяют понимание нюансов, а не факты-пустышки. У каждого вопроса `explain` на русском: почему правильный ответ верен. Формат как в примере трека `polish` (шаг 4), но `track: "tech"` и только `choice`; правила там же.
5. В `state.json`: `tech_last_run = сегодня`, сдвинь `tech_rotation.next_index` на следующий элемент (по кругу).
6. Проверка: `npm install --no-audit --no-fund --no-package-lock && npm test` в корне репозитория. Если тесты упали, поправь файл квиза и запусти снова. Если `npm` недоступен в песочнице, пропусти проверку и положись на CI (см. шаг 8 трека `polish`).
7. Commit и push в `main` с сообщением `lesson: YYYY-MM-DD tech` (урок и файл квиза в одном коммите; перед push сделай `git pull --rebase`).
8. Проверь деплой и доставь урок по разделу «Публикация и доставка». Ссылка: `https://patron93.github.io/daily-learning/lessons/YYYY-MM-DD-tech`. В письме и в чате: номер дня, категория и тема, 1–2 фразы о сути и ссылка. Тема письма: `📚 День N · 💻 <тема tech>`.

## Публикация и доставка (оба трека)

1. После push найди через GitHub MCP (`actions_list`, список запусков workflow `deploy.yml`) запуск для своего коммита (`head_sha`). Жди его завершения, проверяя примерно раз в 30 секунд, но не дольше 8 минут.
2. Если запуск завершился с `conclusion: success`, открой страницу урока через WebFetch (curl из песочницы до github.io закрыт) и убедись, что на ней есть заголовок урока. GitHub Pages иногда обновляется с задержкой до минуты: если страницы ещё нет, подожди и попробуй ещё раз 2–3 раза. Если WebFetch недоступен, успешного деплоя достаточно.
3. Письмо через Gmail на адрес из `profile.md`: короткое HTML-письмо с содержанием, указанным в шаге трека, и заметной ссылкой «Открыть урок».
4. Короткое сообщение в чат (SendUserMessage) с тем же содержанием и ссылкой.
5. Если деплой упал или не закончился за 8 минут: в письмо положи урок целиком (HTML), как запасной вариант, и добавь ссылку на файл в репозитории `https://github.com/patron93/daily-learning/blob/main/lessons/<файл>`. В чате и в письме скажи, что сайт не обновился, и коротко назови причину из логов (`get_job_logs`).

## Формат markdown для сайта

- Спойлеры (если нужны): `::: details Показать ответы` … `:::`. Отдельных ответов к упражнениям больше нет: их заменяет квиз.
- Не используй `{{` и сырые угловые скобки вне блоков кода: VitePress прогоняет markdown через Vue, и сборка упадёт. Дженерики вроде `Signal<T>` пиши в обратных кавычках или в блоке кода. Единственный сырой тег, который разрешён в уроке, — `<LessonQuiz date="YYYY-MM-DD" track="polish|tech" />` (кроме `<sub>` в подвале, как в шаблонах). Строки в `*.quiz.json` тоже не содержат `{{`.
- Первая строка `# …` — заголовок урока, из него строится меню сайта: `# 🇵🇱 День N · YYYY-MM-DD · <тема>` и `# 💻 День N · YYYY-MM-DD · <категория>: <тема>`.

## Правила

- Язык объяснений русский. Польские примеры всегда с переводом. Для новых слов указывай род (m/ż/n) и, если слово неочевидное, ударение или подсказку по произношению.
- Объём: каждый трек читается за 4–6 минут.
- Если пользователь оставил отзыв в `feedback.md`, учти его и не удаляй.
- Если Gmail недоступен, всё равно сохрани урок и сделай push; в сообщении в чат укажи, что письмо не ушло, и дай ссылку.
- Никогда не удаляй историю; только дописывай. Старые уроки (`lessons/YYYY-MM-DD.md`, до разделения) не трогай.
